# 当前实现的注意事项与限制

这里保留仍对使用、排错和优化有效的结论。历史修复计划已移出发布说明；这些条目不是自动执行的待办。判断某个问题是否仍存在，应以当前代码和可复现反例为准。

## 周期与流水语义

**不要混用 `T_clk`、`b_v` 和 `tau_v`。** 前者是完整目标，预算约束本体，等效周期描述训练外壳。每级分别受 T 约束；不能再除以 L、按总节点数等分，或给串联节点各自分配整个窗口。

**L 与测试驱动的观测延迟不同。** L 包含输出捕获，输入服务另有边界偏移。检查连续输入、流水填充、valid 气泡、输出保持和在途 reset，不能只验证最终数学结果。

**预算与 RTL 是两种变化。** 调整模型查询和预算可以改变预测，而相同结构与位置的 RTL 仍可能完全相同。当前物理实现使用完整请求的全局约束；局部等效周期不是每个小模块的真实 ABC 约束。

**放宽分配包络不能制造达标。** 当前模型在没有原始正窗口时可求诊断价格，最后仍按原 T 和完整控制路径判断。扩展反解区间和预算触限也需要报告。

代码入口：[联合预算](../../tools/autopipe/local_budget.py)、[反解](../../tools/autopipe/equivalent_period.py)、[完整评价](../../tools/autopipe/workload_diagnostic.py)。

## 所有权与边界

G 整个归约区域只收费一次；内部 Add 等成员不再独立计价。G 本体不等于所有区域间连线或任意组合残差，S/control 误差也不能转移给 G 吸收。

采样 FF 与采样边界用于解释模型输入；实际设计只计算真实状态、边界及 shared 项。把虚拟采样寄存器加到每个节点上，会同时破坏面积和时序。

不同 capture、共享节点和多个消费者需要共同路径约束。一个共享节点只有一份预算，不能在不同路径分别拥有互不相容的预算。

代码入口：[所有者与图](../../tools/autopipe/workload_demand.py)、[状态及完整计价](../../tools/autopipe/workload_diagnostic.py)。

## 有效位、状态与零代价

声明宽度、结果需求、常零／常一位、编译器 variable bits 和映射后 FF 数不同。当前状态投影仍可能与综合后的实际寄存器规模有差异，宽乘法是重要检查对象；不要用应用专价掩盖特征缺陷。

固定移位和连线可能没有独立算术单元，但仍会改变结果形状、后续工作量和负载。常量／连线的零代价必须有语义依据，不能把缺价或异常静默改为零。

模型预测名义状态不等于物理网表 census。修改事实传播、别名或状态物化时，应同时检查功能、状态收据、计价和周期。

## 搜索结果的解释

当前是有限结构、有限位置和有限预算反馈；完整评分尚未继续驱动新的结构／位置生成。池内最佳不能称全局最优。

模型压力提案仍用摘要权重，其局部结构与完整 G 路径的含义未必完全相同。改变提案或粒度属于候选策略变化，需和纯工程提速分开评价。

D 选中粗结构、与 B/C 相同，或给出 `target_unmet` 都可能是正常结果。目标满足后面积优先；全部违约时违约优先，不能为了让 D 显得更细或更快而暗改排序。

当前独立入口默认每次搜索 300 秒，VUL 以每个块计；首次构建另计。减少候选、缩短预算或跳过计价会影响结果覆盖，不应报告为等价加速。

代码入口：[候选生成](../../tools/autopipe/generate.py)、[配置](../../tools/autopipe/candidate_grammar.py)、[预算反馈](../../tools/autopipe/workload_equivalent.py)。

## 两入口、缓存和并行

VUL 默认通用粒度，Python 的登记 workload 默认专门粒度；对照时匹配 profile 或显式列表。目录同名也不能证明计算源、封装、复位和接口相同。

可复用的 RTL 不等于所有 owner/query 元数据可复用。涉及模型结果的缓存身份按内容包含图、位置、状态、平台/profile、模型、完整请求及局部转换条件，不能只用 RTL 哈希跨 T 或跨平台保留旧元数据。

同形状不同上下文的算子可有不同价格；同一实例不同预算也可能有不同等效查询。缓存键需要反映实际响应输入。

当前部分计价路径使用 `unittest.mock.patch` 临时绑定特征或工艺常量。增加同进程线程并行前应检查全局状态，不能直接认为独立候选就线程安全；`vulrtlgen -j` 现用模块进程隔离。

代码入口：[VUL 适配](../../tools/autopipe/vul_entry.py)、[价格缓存](../../tools/autopipe/workload_final_prices.py)、[Nangate45 runtime](../../tools/autopipe/nangate45_pipeline_runtime.py)。

## 测量、精度与数据职责

- 内部本体延迟、完整 Tmin、请求周期和 setup slack 是不同量；报告必须说明端点与阶段。
- setup 满足不能代替 hold 满足，控制／端口路径也需要检查。
- ASAP7 与 Nangate45 的时间、负载和面积单位必须按 profile 转换一次，不能直接复用数值或重复换算。
- GRT、CTS、最终布线，以及有限修复预算的结果应分别标记。运行脚本完成不等于时序达标或物理签核。
- 验证后反复改进所用的数据属于已消费回归，不能再称未见测试；同源时钟点、负载变体和 producer 分组需要核对。
- 源聚合 median/P95、逐路径误差、银行 max、单源失败分别报告；总体改善不能掩盖关键源或资格失败。
- 当前模型的诊断／外推标记保留，软件可执行不等于完整预测精度已通过。

## 资源身份与文档命名

所有用户文档统一称“当前模型”。参数 JSON 内部历史标识、源码文件名、来源和哈希仍参与兼容或校验，不按文档名称替换；名字带编号不意味着是无用的旧版本。

`--target-backend` 选择当前模型的工艺参数，不启动物理后端。`--circt` 选择 RTL 输出流程；自动模式当前不能与它同时使用。

`--arithmetic-request` 的版本化算术协议与 Python `--source-request` 的源元数据协议不同，不能互换 JSON。

修改模型文件但没有同步发布清单会被拒绝，这是完整性检查，不应绕过。后续扩展应从当前冻结资源建立对照，确认新参数后再统一发布。

## 排查和提速的最小工作流

1. 记录当前提交、子模块和模型资源，准备新输出目录，保留原错误及最小反例。
2. 先用 MAC32、Add512，明确后再扩展 Mul128 或复杂输入；分开测首次构建和构建复用。
3. 分阶段统计构建、提取、结构展开、流水导出、图／特征构造、反解、计价、序列化与装回的时间，并测峰值内存。
4. 查找重复编译、导出、图重建、模型查询、I/O 和无改善循环；根据证据决定优化位置，不预设 Python 或 C++ 是瓶颈。
5. 等价优化比较候选池、选中结构／位置、预测、排序和功能。行为修复另存修复前反例，不为保留旧输出而保留已证实的错误。

相关软件检查：

```bash
python3 -B -m tools.autopipe check-models
python3 -B -m unittest discover -s tools/autopipe/tests -v
python3 -B regression/generator_autopipe.py
python3 -B regression/generator_autopipe_grammar.py
```

按改动选择相关检查。模型预测回归检查已有数值，功能仿真检查算术与周期，两入口回归检查相同源和参数下的候选及 RTL；它们都不能代替新的物理精度验证。
