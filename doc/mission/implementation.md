# 当前实现：编译、候选与完整计价

本文描述当前发布代码。初始任务是研究背景，具体支持范围以这里的实现、模型合同和软件验证为准。

## 编译入口与分工

`vulrtlgen` 是完整 VUL 项目的统一入口。普通生成、原有 `PIPELINE` 流水化、CIRCT 输出及模型驱动选择共用 VUL 前端和模块框架。

| 路径 | 实现 |
| --- | --- |
| 普通 RTL | C++ 解析 VUL、生成模块框架，直接调用 RTLzz 编译计算逻辑 |
| 原有 `PIPELINE` | C++ 按声明的 L 调度计算、插入寄存器，处理 valid、复位和数据对齐 |
| `--circt` | C++ 通过 CIRCT HW/Comb/Seq 优化与输出；调用外部 `circt-opt` |
| `--auto-pipeline` | C++ 提取计算源，Python 搜索和计价，C++ RTLzz 生成候选 RTL，再装回模块 |
| `-m Main.utb` | 生成 Verilator 驱动及 Bash `run.sh`，后者调用 Verilator 和 C++ 编译器 |

自动模式使用原生 RTLzz，不能同时传入 `--circt` 或 `--arithmetic-request`。后者是另一个版本化算术请求接口，JSON 格式与 Python 源请求不同。

主要调用链为：

```text
tools/vulrtlgen.cpp
  → src/rtlgen_rtlzz.cpp / src/autopipe_bridge.cpp
  → tools.autopipe.vul_entry
  → tools.autopipe.generate
      → RTLzz 候选导出
      → 目标工艺 runtime 的 evaluate / optimize
  → 选中核心适配并嵌入 VUL RTL
```

Python 独立入口复用相同的生成和计价实现。源、复位、接口、L、请求周期、工艺和粒度都相同时，才具有直接比较候选与结果的基础。

## 对照方法与支持范围

| 方法 | 当前独立生成入口的含义 |
| --- | --- |
| A | L=1，保留算术结构的参考实现 |
| B | 保留结构，按简单静态代价选择流水放置 |
| C | 在指定结构语法内，按简单静态代价选择结构和流水放置 |
| D | 在有限候选内，以当前模型的完整预测选择 |

VUL 自动模式调用 D。普通 VUL 流水化沿用原生调度，不直接等同于独立入口为论文对照定义的 B。

自动入口需要源码声明 `PIPELINE`，L 来自其第二个参数；支持 L=1～256、带 valid 或无 valid 的块。L 包含输出捕获级，输入服务另有一周期边界偏移，功能检查应与测试驱动的观测时刻一致。

当前自动结构展开主要面向无符号有限位宽整数：乘法有效输入位宽不超过 128 bit，乘法块宽为 2～128 bit；加减法段宽为 1～4096 bit。`0` 保留该类运算的原结构。是否展开还取决于常量、结果需求、位宽和结构归属，不能将输入类型支持理解成模型完整覆盖。

随附九类数学源；Nangate45 的应用实证范围为 MAC32、Add512、Mul128。原始目标中的除法、浮点等研究范围不等于当前 D 已有相应的完整响应模型。

## 候选与寄存器放置

[共享粒度解析](../../tools/autopipe/candidate_grammar.py)从通用配置或登记的 workload 读取两组宽度；显式列表覆盖对应默认值。

| 配置 | 乘法块宽 | 加减法段宽 |
| --- | --- | --- |
| `generic` | `0,4,8,16` | `0,32,64,128` |
| `mac32` | `0,4,8,16` | `0` |
| `add512` | `0` | `0,32,64,128` |
| `mul128` | `0,8,16,32,64` | `0` |

VUL 默认 `generic`，与 Python `--source-request` 默认一致；Python `--workload` 默认使用对应 workload 配置。profile 只选择粒度，不替换计算源，也不根据目录名推断。

每个宽度列表要求不重复，笛卡尔积最多 16 种结构。每种结构导出原生流水候选，并产生静态平衡、依赖深度及模型压力放置。编译器会物化图、状态和所有者信息；完整候选按 RTL 哈希去重。结构数与去重后的完整候选数不同。

D 保留有限的静态种子和模型压力候选，再逐个完整计价；当前默认完整候选上限为 256。它不穷举所有算子的独立拆法，也不穷举所有合法寄存器位置。最终完整评分尚未继续反馈生成新的结构或位置。

同一流水切面必须重新对应状态、寄存器槽位、所有者和约束。正确的数学表达式不足以证明流水周期、valid、保持及复位也正确。

## 时间语义

| 量 | 含义 |
| --- | --- |
| `T_clk` | 完整设计的请求周期，每个流水级分别受其约束 |
| `b_v` | 分配给唯一算术或 G 所有者的本体时间预算 |
| `T_eq,v` | 使采样有效窗口匹配 `b_v` 的等效训练周期 |
| `tau_v` | 量化、复核后实际传给响应函数的等效训练周期 |
| `d_hat_v / A_hat_v` | 响应函数给出的本体延迟和面积 |
| `H_char` | 采样外壳中不属于被计价本体及其他算术的边界消耗 |

固定 L 后，每一级仍受 `T_clk` 约束；不能再把周期除以 L。级内某条路径的预算满足：

```text
Σ b_v + 实际边界 + 所有者间连线 + 一次性裕量 ≤ T_clk
```

并行支路各自受路径约束。共享节点只分配一次，同时满足多个后继和捕获端点；每个节点独立得到的最大窗口不能同时全部用满。

[联合预算](../../tools/autopipe/local_budget.py)以当前所有者 DAG、寄存器切面和捕获端点建立约束，用参考价格形成初始权重。有限预算转移后仍检查全部路径。

原模型的 T 输入描述采样外壳，通常不等于本体预算。实际转换为：

```text
B_char,v(T) = min_p(alpha_p · T - H_char,p - D_other,char,p(T))
B_char,v(T_eq,v) ≈ b_v
(d_hat_v, A_hat_v) = f_type(x_v, tau_v)
```

`D_other,char` 是真实采样消费者等其他算术的时间责任。直接捕获、固定边界且无其他算术时，才能使用解析关系 `(b_v + H_char) / alpha`。含消费者时进行有限扫描和区间细化，不假定响应处处单调。

当前默认反解扫描 32 个区间、每区间最多细化 28 次、容差 0.05 ps，最多保留 3 个根；标准区间为 1～6000 ps。最终适配层对无解查询可延伸至 100000 ps，并记录扩展标记。具体值见[反解配置](../../tools/autopipe/equivalent_period.py)和[消费者适配](../../tools/autopipe/workload_final_adapter.py)。有限扫描不能证明不存在未采到的根。

转换收据保留预算、等效周期、实际查询、残差、本体价格和局部未满足情况。采样虚拟寄存器只用于换算，不为实际设计的每个算子重复收费。

## 完整面积、时序与选择

所有者分为算术本体、G 归约区域及其他功能逻辑。G 内部成员由整个区域覆盖，不再单独计价；重叠归属会被拒绝。

总面积由各唯一组合所有者、S 状态面积及 shared 项组成。时序沿同级真实依赖传播，在捕获位置加入真实数据边界，并单独检查 valid、enable、复位等控制和端口路径。控制响应不能简化为每个算术节点扣一份固定开销。

每个完整候选执行：

```text
图、位置与状态核验
  → 唯一所有者与参考完整预测
  → 联合本体预算
  → 采样窗口反解和实际模型查询
  → S/shared 与完整路径重算
  → 有限预算反馈
  → 保存已完整评价的最好结果
```

[预算反馈配置](../../tools/autopipe/workload_equivalent.py)默认有初始轮和最多 3 轮反馈，每轮最多 3 个提案，每份预算最多 3 个对角根向量。根的所有混合组合并未穷举。

若原请求没有正预算窗口，当前适配会尝试较宽的分配包络以得到诊断价格；实际请求、S/control 上下文保持，结果仍按原请求评价，不能由包络放宽报告为原请求达标。

排序规则为：完整预测满足请求时优先总面积；全部有价候选违约时优先完整周期违约，再比较总面积和稳定规则。选择保存在[生成流程](../../tools/autopipe/generate.py)中。

| 情况 | 含义与处理 |
| --- | --- |
| `target_met` | 完整模型预测满足请求；物理 setup/hold 仍需实测 |
| `target_unmet` | 输出有限候选内按规则选中的有价后备及剩余违约 |
| `cost_uncovered` 或无完整预测 | 不把缺价当作零代价或有价违约；没有可选候选时失败 |
| 搜索超时／编译错误 | 保留错误和已有痕迹，不报告完成选择 |

局部 `d_hat_v > b_v` 是局部响应未满足诊断；是否满足完整目标由全部路径重算决定。预算变化不等于 RTL 已改变；实际物理实现仍使用完整请求的全局约束。

## 输出与后续维护

每块 `.autopipe/` 保存请求、搜索日志、候选池、选择、核心 RTL 和预算评分轨迹。完整 VUL 输出由终端打印顶层路径；用 `-t` 时通常为 `top.sv`，用 `-m` 时通常为 `sim/top.sv`。

当前模型是后续工作的唯一发布基线。优化先核对[模型资源清单](../../vullib/models/autopipe/manifest.json)，保持既有预测回归；语义修复、特征扩展、候选策略改变和重新拟合分别说明并验证。命令见[生成与测试指南](../autopipe.md)。
