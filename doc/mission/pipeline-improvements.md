# 流水放置与关键路径改进方向

以下是从当前模型和已测流水实现得出的维护方向。当前 D 先生成有限结构和放置，再完整计价。在一个固定候选内部，预算反馈会调整算术本体的查询条件。这里提出的下一步是让完整的路径评分再指导放置和结构提案。 [当前实现](implementation.md#候选与寄存器放置)

## 什么时候继续搜索

每个流水级都受同一个请求周期 `T_clk` 约束。已有预测达标的候选时，按总面积选型，允许部分级有余量。全池预测违约时，按最差路径的周期违约量推进搜索。级间周期差用来寻找可利用的余量。如果 STA 揭示了预测漏掉的瓶颈，先检查实际路径的计价与匹配端点。 [时间语义](implementation.md#时间语义) · [完整评价与排序](implementation.md#完整面积时序与选择)

## 用完整路径评分指导候选生成

1. **先在固定结构内移动切点。** 从完整评价给出的最紧捕获路径出发，按前驱、后继、固定端口及合法调度组确定允许级号。在相邻级尝试前移或后移整个调度单元。逐个重新物化候选，计算跨级活跃值、寄存器槽位、G 区域归属和数据、控制、端口路径，再按原请求计价。保留现有候选作为对照，限制新增提案数，并用稳定规则处理并列。 [候选生成和完整计价](../../tools/autopipe/generate.py) · [RTLzz 调度组](../../rtlzz/src/backend/pipeline.cpp)
2. **再沿最差路径提出局部结构变化。** 同级串联的多个所有者优先尝试在已有合法边界处加切面。若单个宽算子主导，针对该算子尝试乘法分块、加减分段或等价改写，让不同算子可采用不同粒度。部分积和归约树的切分遵守精确中间位宽、符号、进位与截断约定。对每个新结构重新放置和计价，记录它是否改变了候选覆盖或选择结果。 [乘法展开入口](../../rtlzz/main/arithmetic_workload.cpp) · [部分积与归约级](../../rtlzz/src/backend/mul_split.cpp)
3. **沿实测路径核对估时。** 对齐同一 RTL、工艺、请求和测量阶段，记录算子本体延迟、级内组合延迟、完整级需求及整块 `Tmin`。对预测达标而实测违约的候选，定位误差来自算术或 G 本体、所有者间路径、状态控制还是端口边界。先用当前冻结参数复现。若确认修复改变预测或选型，保留修复前反例，验证通用修复及相关回归。 [模型职责与资格](models.md) · [测量口径](pitfalls.md#测量精度与数据职责)

## 代表性反例与试验方向

下表采用 ASAP7 的早期软件候选归档和后续论文 D 实现。`T` 为完整设计请求周期。层级片段取原 GRT 最差 setup 路径上经过该层级的内部首末引脚。早期选择见研究归档 `W2-D-budget-response-all-20261115-v2`。后续论文的 RTL 身份、选择记录和物理读数见 `autopipedata.md` 表 5 对应的 `matched.json` 与原运行报告。

| 负载 | 已观察到的现象 | 优先尝试 |
| --- | --- | --- |
| Horner64 | 早期 L=8、T=1500 ps 的分块候选在末级积累归约。后来 L=8、T=950/1150 ps 的实现选中 16 位分块，奇数级做部分积乘法，偶数级做归约。T=1150 ps 时模型预测 S1 最紧，STA 最紧级是 S3。 | 对每轮乘加同时搜索粒度和切点。比较部分积归约纳入当前系数加法的方案，并核对 64 位模截断。 |
| Barrett64 | L=4、T=1800/2150 ps 的宽乘法方案实测满足请求。L=8、T=900/1100 ps 的 32 位分块方案在 S6 上串接 G183 与 129 位减法。G183 本体预测约 525–538 ps，路径层级片段约 947–962 ps。 | 先试在 G183 和减法之间切分，检查后继比较、选择和输出捕获能否利用尾级余量。若单独的归约级仍违约，再考虑分层归约和 G 计价。 |
| Karatsuba256 | 早期 L=8、T=2000 ps 的候选把乘法、加减与重组集中到 S8。后来的 L=8、T=1400/1750 ps 实现的 S8 预测约 941–944 ps，STA 最差路径已移至 S1 的 64×64 叶乘法。 | 对末级集中的布局先调重组依赖的切点。对后续布局单独尝试拆分关键叶乘法，同时比较未受影响的叶算子和新增寄存器的开销。 |
| NTT8×64 | 早期候选的串行路径集中在 S15、S16。后来的 L=16、T=800/950 ps 实现预测各级约 676–778 ps，STA 最紧级 S11 约 1483 ps。该路径经过 128×65 常数乘法 `rtlzz_owner_305`，本体预测约 576–580 ps，层级片段约 1285–1300 ps。 | 先复现该常数乘法的延迟低估，再比较原乘法、部分积分块及常数 `2^64 + 2^32 - 1` 的移位加减实现。检查取高位前的精确位宽和低位进位。 |

NTT8×64 的计价检查从已知一位对应的部分积工作量入手。当前分支更新这项特征后重新计算面积，延迟沿用此前的计算结果。用原查询、本体预算、实际等效查询周期和同层级 STA 路径复现这一差异，再检查同类常数乘法上的表现。 [当前乘法计价实现](../../tools/autopipe/workload_diagnostic.py#L105)

## 对照与验证

- 固定工艺、源码、复位与 valid 语义、接口、`L`、`T_clk` 和模型资源。保存获选 RTL、布局、计算图、状态、所有者查询及排序记录。对 VUL 和 Python 两个入口使用同一份提取源与配置。 [生成与测试指南](../autopipe.md)
- 用 MAC32、Add512 验证算术、位宽与截断、流水拍数、valid 气泡、保持及复位。用 Barrett64 的 S6 和 NTT8×64 的 S11 检查原瓶颈，在 Horner64 和 Karatsuba256 上对照切点和算子粒度的变化。保留诊断和外推资格。 [软件与功能检查](pitfalls.md#排查和提速的最小工作流)
- 对照每级预测和 STA，报告最差 setup 路径所在级、整块 `Tmin`、hold、总面积、搜索耗时和峰值内存。仅存整块最差路径的配置只填该路径所在级的 STA，其他级留空。已用作调试的物理结果登记为已消费回归。 [测量与数据职责](pitfalls.md#测量精度与数据职责)
