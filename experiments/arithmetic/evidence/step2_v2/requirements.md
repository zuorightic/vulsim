# 第一章：修订后的实施计划

## 1. 目标、范围与完成边界

给定组合逻辑、目标平台、端到端延迟 `L`、启动间隔 `II=1` 和目标时钟周期，在功能及周期契约不变的前提下，自动选择算术结构、合法拆分粒度与寄存器位置。D 在声明的候选与模型支持范围内，优先选择预测满足时钟且预测面积较小的实现；是否真的满足时钟、面积是否改善，由统一后端实测判定。不承诺全局最优、模型预测一定准确，或每个平台、每个案例都获得收益。

L 是输入约束。`PIPELINE(latency=L)` 对应 RTLzz 内部边界数 `N=L-1`；RTLzz 独立命令行中的 latency 参数含义必须在驱动中显式转换。主实验 B/C/D 对同一案例固定同一 L，不自动增减 L。A 为统一输入/输出寄存器壳包裹的原始组合核，通常 L=1，单独报告。跨 L、多个目标周期扫描、物理布局坐标优化不属于首版必做项。

“寄存器位置”是各计算组的流水级归属以及跨级值的共享延迟链。固定 L 不固定边界经过哪些节点；模板提供合法切分粒度，调度器决定边界是否使用。触发器在芯片上的坐标由物理后端决定。

最低功能范围包括五档整数位宽、三类代表结构、四个平台的独立训练与完整对照。乘法必须有真正的、参数化的内部拆分；不能只在完整操作前后加寄存器。动态商余必须完成全部五档位宽的接入、正确性和评价，是否开放内部拆分单列支持清单；浮点亦如此。未开放内部切分时，相关区域在 C/D 保持原子性，不能宣称该类内部拆分收益。

通用性分三层验收：

1. **生成器能力**：通过位宽、结果宽度、分块等参数生成图和 RTL，不为每个宽度手写一套实现；检查若干非二次幂宽度以发现尺寸硬编码。
2. **模型能力**：在声明的操作、位宽、模板、目标和后端域内预测，并通过独立微基准测试；未知平台或域外输入明确拒绝。
3. **实测能力**：四个平台完整执行正式与保留案例，保留不可行、超时和失败；失败记录满足结果完整性，不等于对应功能支持或模型质量已经验收通过。

以上通用性以**受支持源码能生成的组合DAG、已实现展开模板及已验证模型域**为边界。需要分别说明：能在已显式展开的节点之间自动安排流水级、能把一个原本不可切分的大操作展开成可切分子图、能自动替换应用算法/数值方案（如更换Sigmoid近似）、能改变有状态架构；四者不是同一能力。首版前两项按支持清单推进，后两项仅按本章§6.4–§6.5预留；没有“输入任意AES/Sigmoid名称或任意RTL即可自动拆分”的保证。

可以按§10.10分阶段交付，每个阶段单列已验收的操作、位宽、平台、模型域和记录数量。阶段验收不等于43案例、四平台和完整五档位宽全部完成；8位和128位均保留正式功能及四组PPA评价要求。确需改变最终范围时，先提交容量、开发/交付时间及结论影响证据再讨论，不能通过阶段划分将未完成范围改成选做。

### 3.2 单位、面积和阶段

驱动对外统一 ps、µm²，保留原始值、原始单位及换算依据。每个平台读取 Liberty 并核对 OpenSTA/OpenROAD `report_units`，也核对 ABC `-D` 所要求的单位；不能直接将 ASAP7 的 SDC/ABC 数值或面积比例复制到其他平台。ASAP7 平台缩放与 OpenDB 面积换算沿用已核验逻辑，其他平台独立验证。

统一主表阶段：**CTS 后全局布线及寄生估计（grt）**。综合映射＋STA 用于大规模采样及辅助指标；详细布线＋提取＋STA 用于预声明代表方案复核。三个阶段的数据分别建模、分别报告，不能混作同一标签或用较早阶段补齐主表。

grt 可行性要求阶段完成、时序覆盖完整、冻结 typical/TT 条件下 setup≥0。hold 始终报告，不参与 grt 的通过门限或并列排序；负值标记风险，零附近标记待复核。详细阶段如要宣称 setup/hold 同时满足，须有完整提取、setup/hold≥0、覆盖完整及路由 DRC=0。ASAP7 既有 5ps 工程复核带保留；其他平台在试跑时按预声明规则冻结各自复核带，不能把 5ps 当跨工艺噪声底。所有 typical/TT 结果均标记 `multi_corner_signoff=false`。

面积采用一致定义的标准单元面积，功能组合、顺序和物理专用单元分列，排除 CORE_SPACER 的策略须能映射到各库。面积原值只在同平台/同设置内比较；跨平台报告逐平台结果及相对各自基线的比值，不直接平均原始 µm² 或 ps。

### 3.3 接通验收与历史关键路径

每个新增平台先完成小型加法/寄存器核，再完成同一个参数化乘法探针的 synth→grt→final；核验 I/O 约束、setup/hold、未约束端点、面积、网表、提取和失败诊断，记录墙钟、CPU、内存与实际线程。超时或失败保留阶段，不为完成表格反复换点。

旧 ASAP7 路径证据继续有效：综合 clk→Q 47.352940ps、Q→D 947.107448ps、setup 9.885993ps、uncertainty 20ps，合计 1024.346381ps；起终点与乘法数据锥的连接证据在原推进记录中。它支持继续研究内部拆分，不证明新模板必有收益。ABC 333.21ps 是单独的映射诊断，未经路径和口径核对不与完整 STA 计算误差倍率。已有两点 SDC 控制实验亦只解释其实际实现及上下文。

## 4. 算术语义、参考模型与宽位宽验证

### 4.1 整数

首版统一无符号输入，W∈{8,16,32,64,128}。加减及截断乘法按输出位宽取模；完整乘法产生 2W 位，完整双乘积和需 2W+1 位。128×128 的完整乘积是 **256 位**，双乘积归约可能是 **257 位**；前端、BEIR、复位求值、RTL 发射、软件模型与测试驱动必须支持这些中间值，不能将“支持 128 位”误实现为全部结果均截成 128 位。

动态商余统一：d≠0 时 `a=q*d+r, 0≤r<d`；d=0 时 `q=2^W-1, r=a`。内部先用 `safe_d=(d==0 ? 1 : d)`，所有 Div/Mod 只消费 safe_d，再按对齐的标志选择结果。复位表达式同样有定义，不能只保护最终输出而让内部除零。单独 `/`、单独 `%` 与商余联合实现分别登记；只有图中显式共享同一实现时才共计成本。

动态移位采用本项目共同包装：0≤s<W 按无符号逻辑移位，s≥W 输出零；先生成安全内部移位量，再选择规定结果。各组及参考一致，不依赖 C++ 越界移位行为。常量移位、动态移位分开计费和采样。位选/动态写入/Lookup 等已有操作保持其已核验语义，越界策略须显式降低或拒绝，不能静默取模。

Python 任意精度整数作为独立参考，显式掩码和范围检查。C++/Verilator 驱动用 limb/多字表示，不经过 uint64_t 截断，不依赖宿主有符号溢出。组合层验证等价，流水层用队列 scoreboard 检查固定 L 的事务序列。

### 4.2 浮点

保留 `arithmetic-semantics-v1`：binary32 乘法，输入/输出为位模式，RNE ties-to-even，渐进下溢，不用 FTZ/DAZ，tininess after rounding，规范 NaN `0x7fc00000`，sNaN 与 0×Inf 的 invalid、符号零及五位异常标志按现有约定。串联两次乘法分别舍入，flags 按原约定 OR，不融合成 FMA。

复用精确整数浮点参考及可选 SoftFloat 独立核对；原可选参数继续保留。不因训练或平台变更放宽语义，也不以随机结果一致替代特殊值、非规格化和舍入边界检查。

### 4.3 验证范围

五档位宽全部检查零、全 1、最高位、进位/借位、完整/截断结果、移位边界、除数大于被除数、d=0/1/2^k/非2幂及大商余。8 位乘法和商余可穷举；宽位宽采用定向、单热位、多 limb 边界、固定种子随机和可承受的形式验证。非整齐位宽至少检查 12/24/48/96 位的生成及功能，作为参数化能力证据；未纳入模型验证或物理矩阵时明确其范围。

流水验证必须连续输入、气泡、填充/排空、长短路径合流、共享值、多消费者、数据与 flags 对齐、在途事务复位及复位后重启。不得在每个输入后清空流水线。保留原生发射器为主路径；`VUL_REGRESSION_CIRCT=0` 时继续全部软件/原生检查，仅明确 SKIP CIRCT 专属项；启用而缺工具则给出诊断，不能跳过整条算术回归。

### 4.4 数值契约的扩展字段

首版仍按§4.1无符号整数和§4.2 binary32的固定语义验收。后续公共接口中的 `semantic_profile` 应可关联逐端口/操作的位宽、符号与数值格式；扩展字段至少能描述二补码、定点小数位、中间精度、缩放位置、逻辑/算术右移、舍入、截断、模溢出/饱和和异常策略。可以用位向量加元数据/库函数降低，不要求首版新建全部定点类型或BEIR内建指令。格式无法解释时明确拒绝，不能忽略字段后按无符号核心执行。

定点契约采用明确的W/F定义：W为总编码宽度，有符号时包含符号位，F为小数位数，解码值为所声明有符号或无符号整数乘 `2^(-F)`；输入/输出可以不同，不能只写含义不一的“Q格式”。每次乘加扩宽、重标度、舍入和饱和的位置都是语义的一部分，优化和拆分不得跨这些位置重排或提前截断。前端已有有符号视图/移位基础，不等于本实验已经验收有符号拆分、定点语义和D模型覆盖。

近似运算保留两个参考：高精度数学函数用于评价近似误差，独立的有限位参考用于逐位验证硬件。固定系数/表值/格式后，C/D结构变换默认要求与同一有限位参考逐位一致。若更换LUT、PWL或多项式导致编码结果变化，即使均满足同一个数学误差上限，也属于另一个明确版本的数值方案；不得混入本计划保持功能不变的C/D结构候选。联合搜索误差与PPA属于扩展协议，须另冻误差门限及比较方法。

## 5. 区域、候选和编译器接口

```text
源码＋L/II＋目标平台＋目标周期＋方法配置
  → 既有前端与 BEIR/BEOPT
  → 区域保护/识别、参数化候选展开与合法组
  → B/C 静态权重，或按平台加载 D 模型
  → 固定 L 下的整组调度及寄存器位置选择
  → 共享寄存器链、valid/reset、原生 RTL
  → 功能与周期验证
  → 已选 RTL 的同平台后端评价与结果归档
```

C++ 负责图变换、合法性、代价消费和调度；Python 负责数据采集、训练、候选驱动、后端和报告。模型训练离线执行。编译器推理不隐式启动训练、Yosys 或 OpenROAD；可由驱动预计算成本表，也可加载可移植模型，但两种入口必须消费相同冻结特征和模型内容。

配置至少包含 `target_platform`、`platform_profile`、`cost_mode`、`model_bundle`、`candidate_policy`、L/II 和目标周期。模型包嵌入目标库/流程身份，加载时校验。缺失或错配模型明确报错，不能悄悄使用 ASAP7 或 C 的权重代替 D。用户显式选择降级时另记方法身份，不能继续计作正式 D。

区域机制复用优化前语义保护及隔离优化。v1 前端只登记 `vularith::F32MulRNE`；没有任意 helper 或外部算术库的通用结构识别。整数模板可直接识别 BEIR Mul/Div 等并建立区域/组。保留同一浮点语义 API 时可以替换展开模板，无需为每种实现必然新增前端名字。

所有图改写维护稳定 region_id、输入/出口、成员、语义、模板及分组版本。区域非重叠、成员唯一、原图/收缩图无环；不得跨区域内部节点 CSE。组合图与物化图的区域数量检查无条件执行，清空一方元数据必须拒绝，两方均无区域继续兼容。节点替换、DCE、常量出口、编号重排和寄存器所有权也须检查。

四组共用相同区域保护与隔离优化：区域内运行既有 BEOPT；跨组件符号与静态事实传播可能受接口隔离限制，字面常量仍可参与化简。这是优化范围限制，不预判物理影响方向。manifest 复用 `sharing_policy`、模板和语义版本追踪，不为此增设实验组。

### 5.1 公共扩展接口：语义与展开、候选与调度

以下是后续实现契约，接口名是建议名；可用现有结构体扩展和静态登记实现，不强制引入动态插件系统。首版在步骤二/四/五/七落实核心运算时共用这些边界，避免让选择器和调度器依赖 `mul32_split16`、AES或Sigmoid的专用分支。

| 接口职责 | 输入/输出的最低内容 | 首版实现与后续预留 |
| --- | --- | --- |
| 编译请求 `ArithmeticRequest` | 既有平台/profile、成本模式、模型、L/II、周期；语义profile和候选策略版本 | 贯通CompileOptions、PipelineV2、VUL bridge和命令行；首版支持核心profile，其余明确未支持 |
| 语义与展开 `ExpansionProvider` | 受支持BEIR节点或登记语义标识＋端口/格式＋参数 → 资格判定、真实组合子图、端口映射、模板/语义版本及拒绝原因 | 参数化Mul和既有FP展开走公共路径；预留Lookup、进位链、GF和近似函数的提供者 |
| 模板/候选登记 `TemplateRegistry` | 语义标识、实现ID、参数schema、适用条件、确定性生成顺序、原始实现、代码版本/哈希 | 首版允许静态注册；C/D共用有序合法结构清单和K，保留原始实现，不按应用名隐藏改候选 |
| 图与合法组 `GroupContract` | region_id、成员/输入/多出口、不可分组、可切分粒度、跨组活跃值与共享关系 | 沿用非重叠区域及组约束；首版不强制嵌套区域，复杂模板可展平为成员唯一的组；边界是允许切分，非固定级号 |
| 统一代价 `CostProvider` | 操作/组/阶段图特征＋平台/阶段上下文 → 独立时延、组合/状态成本、单位、支持状态、来源/版本及裕量 | C消费固定抽象表，D消费冻结模型；完整模板和展开成员选一计费，阶段结构变化后重查；扩展不继承未验证覆盖 |
| 调度与物化 | 真实DAG＋组约束＋成本上下文＋固定L/II → 初始/最终级号、决策、共享链、valid/reset/flags和RTL | 核心与新增模板复用同一调度器；不要求用户指定寄存器位置，不修改原有状态机/握手契约 |
| 参考与验证 | 语义/实现profile、独立参考、向量/等价规则 → 组合等价、周期、复位及必要误差报告 | 逐位参考和数学误差分开；新增模板携带验证入口，不以“生成了图”代替功能验收 |
| 能力及结构报告 | 语义/模板/特征版本、图/调度/RTL哈希、候选/位置轨迹及不支持原因 | 分别报告接口已预留、能生成、已验证、能内部切分、C已选择、D模型已覆盖/已选择、PPA已评价，禁止一个supported布尔值包揽全部结论 |

普通、可内联且在前端支持范围内的helper可以直接生成已有节点图，无需先新增一个语义内建。登记语义API用于需要保持操作身份、禁止不合法重排或枚举实现的情形；不承诺识别任意C++库调用、黑盒函数或任意Verilog模块。现有入口以VUL/受限C++降低为主，外部RTL/网表导入另列扩展；只有名字和延迟摘要的黑盒可在有明确实现/模型时保持原子，不能宣称能在其内部插寄存器。

真正内部切分的展开必须在**代价查询与调度之前**把子图及合法组交给BEIR，并保留规范化后的映射。仅把Lookup时延写成多层Mux的估计、仅在RTL发射/CIRCT/Yosys中展开，均未向当前调度器开放这些内部边界。核心规范化若已生成真实、可调度的选择图，可直接复用，不因新增接口重复开发。若优化把模板合并回大节点，需恢复合法映射或报告该候选不再可内部切分，不能保留名义组数充当证据。

### 5.2 扩展接口在首版的验收边界

首版接口完成至少以**真实核心实现**证明链路：参数化Mul的原始/两种分块候选及已有FP原子区域携带显式语义/模板版本，经统一请求、分组、C成本和D查询进入同一调度/报告流程；各实现按原步骤验收，不为证明接口强行开放FP内部边界。相同模板的多实例和不同参数不得依赖固定信号名或NodeId。

对未登记实现/数值profile、模板参数越界、语义不一致候选、丢失/重叠分组和模型覆盖缺口给出有定位的拒绝；低层前端恰好能表达某操作也不能绕过实验profile检查。只提供同一schema能表达的新增图/模板时，应增加提供者、登记项、所需模型/参考和测试来接入；若新增语义或特征维度，按§11升级公共schema及受影响版本，不伪称无需任何迁移。

首版为扩展输出能力清单和版本化接口说明即可，不强制提交AES/Sigmoid的空实现、未训练模型或每种扩展的占位类。此处“预留完成”以核心公共路径可用、扩展契约清晰及未支持输入能拒绝为准；只有某扩展实际实现并验证后，才将它从预留状态升级。

### 5.3 展开产物的不变式与前置自检

**后端操作集不变式。** 对现有BEIR后端接入的新模板，完成其登记的降低/规范化后，只能向成本、调度、复位求值和RTL发射交付**当前实现版本及所选路径共同支持的BEIR操作集合**。检查项包括 `OperationKind`、适用的 `OpCode`、操作数个数/类型/数组形状、符号与索引规则；仅在枚举中存在不等于这些消费者都支持。高层语义标记允许在明确的展开阶段暂存，但必须在规定交接点消除；不得将未降低的GF/近似函数标记或opaque Call直接交给现有后端。GF→位运算、组合LUT→Mux等沿用这一规则，模板登记不能自行扩大可接受操作集。

模板/消费者声明操作支持规则并版本化，可用静态检查函数实现，不强制新建动态注册系统。展开后立即校验，规范化/清理改变图后在成本与调度前再核验，物化后核验新增寄存器连接及最终图；启用CIRCT时另外核对其支持范围，禁用时不因CIRCT不支持而跳过或拒绝本来合法的原生路径。数值成本或D模型支持域另由CostProvider检查，不能以操作集通过替代模型覆盖。无效产物在模板验证阶段给出模板/区域/节点及不支持维度，避免依赖后续封闭switch兜底才发现；原有throw/断言仍保留为最后防线。

这不是永久禁止新增BEIR操作。确需增加op kind/opcode时，先按§11升级IR/特征及相应接口版本，补齐该路径的优化/常量与已知位语义、成本、调度、复位和发射支持及受影响验证，再允许模板使用；本次“预留接口”不表示这些支持已经具备。

**位宽与形状不变式。** 每个模板声明输入/出口及关键中间值的宽度关系、符号和有意截断点。前置检查覆盖正位宽、常量limb数量/高padding、operand与被引用signal的类型一致、driver与结果类型关系，以及Slice/Concat/扩展/选择分支/索引的尺寸和范围；动态索引/移位核对其安全包装或已证明范围，不能依赖测试值。完整乘积保留两输入语义位宽之和，双乘积归约保留所需最高进位，显式输出截断另登记；归约各层必须按其实际扇入计算所需位宽，不能一律只加1或固定为32/64位。

AddCarry的carry为1位，计算结果按声明的BEIR位宽取模；若模板承诺保留完整进位，其工作精度必须足够且后续才按指定位置截断，不能把所有AddCarry结果硬性断言成某个固定W+1。普通模运算、合法的宽度优化和有意截断继续允许，可由显式Cast/ZExt/SExt/Trunc/Slice或版本化操作语义表达；不能仅靠SystemVerilog隐式表达式尺寸、C++整数提升或宿主窄类型取得期望结果。优化缩宽须保留宽度来源/已知位证明及出口语义，物化共享链的所有limb和尾位也要核对。

这些是编译期可重复执行的产物校验，针对模板实例参数执行，不代替生成器本身的边界/非整齐宽度测试、独立数值等价和RTL仿真；尤其不能由“类型/位宽通过”推出发射器不会再发生隐式截断。对应失败记为展开/图契约错误，不记成时序不可行。

### 5.4 展开资格与固定L调度结果分开

`ExpansionProvider`回答语义、位宽/形状、模板参数和生成规模限制是否允许展开；返回合法子图后，调度器才根据同一图/合法组、固定L/II及本组成本上下文判断放置。展开成功不保证存在满足预算的调度，调度失败也不能反写成该模板不支持此位宽。调度/物化自身的类型、元数据或级号错误另外定位，不并入模板资格或资源不足。现有 `Graph::schedule`/`build` 已可能在 `validateProgram` 前拒绝，后续结构化诊断应覆盖这些出口及最终校验，不能只解析最后一个异常字符串。

§9.2中的失败和候选拒绝至少使用下列可稳定统计的原因码，名称随schema版本冻结；明细保留原始诊断和发现阶段，不要求每个拒绝都变成整案例失败：

| 原因码 | 判定边界与必须保留的依据 |
| --- | --- |
| `template_ineligible` | 输入语义/形状、参数或声明的生成规模不在模板支持范围；属于资格拒绝，未宣称已展开 |
| `unsupported_backend_op`、`invalid_expansion_graph`、`width_contract_violation` | 展开/规范化产物不满足§5.3或既有区域/组不变量；是实现/接口缺陷，不能算预测时序违约 |
| `cost_uncovered` | C计费规则或D验证支持域缺失；记录具体维度并保留uncovered状态，不当成无穷延迟或不可行标签 |
| `schedule_group_over_budget` | 有适用于当前上下文的不可分组延迟下界超过其可用数据预算/抽象cap，附组/路径、单位和下界依据；增加L不必能消除单组超限 |
| `schedule_latency_lower_bound` | 有可核验的阶段数/合法边界下界证明所需阶段数大于固定L；附图、预算、组依赖和下界，只在这些前提下称L不足 |
| `schedule_no_placement_found`、`schedule_search_limit` | 当前策略没有找到合法放置，或达到尝试数/时间/资源限制；前者附策略/尝试范围，后者保留实际消耗，均不自动宣称数学上无解 |
| `schedule_validation_error` | 找到/物化的方案违反依赖、分组、共享链、位宽或报告一致性等不变量；保留缺陷诊断，不能以predicted_infeasible掩盖 |

C的cap使用抽象单位，不得据此生成物理ps违约结论；D的下界/预算与不可行结论明确为冻结模型及其支持域内的预测，不能冒充物理不可行证明。某次移动的单级/单上下文超限可记录局部拒绝，对整个候选作下界不可行判断则须覆盖其所有允许的级/路径上下文。没有合法的路径/阶段下界时保留“未找到放置”，不把任意启发式失败或简单时延总和除以周期改名为“L不足”。主实验不自动加L、放松周期、拆开原子组或借最终PPA重选；可预声明的诊断另列，原始失败保留。

## 6. 参数化结构与拆分范围

### 6.1 乘法和乘加：必做内部拆分

将现有 `expand32` 重构为按 W、结果宽度 R、块宽 b、归约策略生成的模板。五档 W 都有完整乘积与显式截断接口；保留原始 Mul。首批分块采用 b=W/2，增加 b=W/4 作为第二粒度（最小块宽 2，按支持表过滤），C/D 共用相同模板。非整齐宽度处理尾块、零填充和精确进位，不以固定 16/32/64 索引拼接。

先生成块乘积，再按带足够进位位宽的归约层合并，最后截断/拼接。最低交付一种正确的归约结构与两种可用粒度；CSA/Wallace 等更多算法列为扩展。合法组围绕部分积和归约层建立，多个相邻组可放同级。128 位模板不能只创建 32 位模板实例而预先手工固定级号。

乘加保留每个原始运算的截断位置；低 W 位乘积、完整 2W 位乘积及后接截断分开处理。模板资格检测读取规范化图、类型和有效事实，不能仅凭输出名字或零扩展形状误识别。未支持情况明确拒绝，不能把未展开图标作成功拆分。

验收覆盖所有五档 W：独立参考、图/组合法性、至少一种配置的真正内部寄存器、连续事务行为；新 C 下自然入选原实现时，使用单独声明的模板功能验收证明拆分能力，不把强制模板结果混入 C 的正式选择。

### 6.2 动态除法和取余

必做完整 Div、Mod、共享/未共享商余的五档接入及安全包装。后端能够优化 `/`、`%` 不等于编译器已获得可切分的内部区域。完整除法不可行仍保留实测，不改成 II≠1 的循环迭代单元。

内部拆分若实施，优先参数化 radix-2 恢复余数除法：W 个空间步骤，按预声明迭代组粒度形成合法组，寄存器传递部分余数、商、除数、剩余被除数和除零标志。先验证小位宽，再扩至五档；只有实际通过的边界列为支持。完整商余接入是必做，除法内部拆分仍是额外结构能力，不能混淆两种完成状态。

### 6.3 binary32

复用已接入的位向量组合实现和区域身份。正式完成 F1/F2/保留图的 VUL 接入与参考验证。初版可保持整个浮点区域不可分，C/D 只在完整操作之间调度；若开放尾数乘法、规格化或舍入段，作为原区域内部子组表达，保持 GRS 和单次最终舍入，不能建立重叠原子区域。浮点加除、其他精度和舍入模式仍为扩展。

### 6.4 运算结构支持清单与扩展顺序

以下按能力登记，表内“基础已有”只说明存在源码/节点基础，仍须按新profile和成本接口验收；“预留”不是当前可用或新增首版算术范围。

| 结构族 | 参数/语义及图要求 | 首版与扩展边界 |
| --- | --- | --- |
| 整数Mul/MAC、乘积归约 | 位宽/符号、结果宽度、截断位置、块宽、尾块、归约结构及合法组 | 无符号五档与两粒度内部拆分仍必做；有符号/混合符号另验 |
| 加减、AddCarry、比较/归约 | 进位/借位、扩宽、溢出、串并行拓扑与共享 | 基础操作必做；分段进位、宽加法内部组和更多归约算法预留，不能因C给常数1便判定物理无需拆分 |
| Div/Mod/DivRem | 安全除数、共享身份、空间展开、步骤粒度及全部中间状态 | 五档完整接入必做；商余内部组仍为扩展，不改变II=1 |
| 位逻辑、移位、旋转/置换 | XOR/AND/OR/NOT、拼接切片、比较、移位边界；常量旋转/字节置换可降低为布线，动态版本另计费 | 复用已有基础；算术移位随有符号profile验收，尚未支持的动态操作明确拒绝 |
| Lookup/Case/Mux网络 | 表值/哈希、元素/索引宽度、可达范围、默认/越界和优先级；内部切分须真实展开选择图 | 核心合法选择及统一计费继续按§7.1实现；通用Lookup内部子图/分组作为应用试点的优先扩展，不把计费图当可调度图 |
| 有符号及定点 | 二补码、W/F、中间精度、缩放、舍入、截断/饱和，按§4.4降低并验证 | 保留格式/语义接口；首版实验域仍无符号，定点Sigmoid试点前落实所用子集 |
| GF(2⁸)与AES S-box | 多项式 `x⁸+x⁴+x³+x+1`（0x11b）、字节映射、xtime/常量乘/异或；S-box可登记LUT、布尔网络或复合域实现 | 可由库函数展开到已有位运算，不要求专用GF内建；不同S-box模板须保持同一8→8位函数 |
| Sigmoid近似 | 输入域、格式、表/分段/系数、端点/饱和、数学误差和有限位参考 | 先固定一种LUT或PWL实现的试点；多项式及多方案搜索按§4.4分版本 |
| binary32乘法内部 | 尾数乘法、规格化、舍入/打包子组，完整传递GRS、指数、符号及flags | 首版允许原子；只有实际开放并验证内部寄存器后才能声称复杂浮点内部拆分 |
| 浮点加减/比较/转换 | 特殊值、对阶、舍入/flags；整数/定点↔浮点规则 | 预留扩展；binary32乘法已有不等于完整浮点表达式可用 |
| exp、倒数/除法等函数 | 输入域、精度、特殊值、误差或正确舍入约束及实现版本 | 直接浮点表达式Sigmoid的扩展路径；LUT/PWL试点不以前置实现这些函数为条件 |

Lookup展开优先采用声明过的Mux/布尔结构及层级组；按真实表大小和图规模设生成上限并报告超限，不能为扩展把任意大ROM无条件指数展开。常量组合表与同步ROM/宏单元分别登记；带固有延迟的存储器不直接套用零延迟DAG展开。表索引、各级选择位和多出口数据需像普通跨级值一样对齐并计共享状态。

### 6.5 AES组合轮与定点Sigmoid：可选应用试点

这两个试点用于检查公共接口是否能复用到已有六个整数家族之外，不替换核心43例，也不要求首版完成。分三批扩展：

1. **应用所需的第一批**：以§5公共路径为基础，按试点需要实现真实Lookup展开/分组、GF库降低和所需定点子集；各固定一种AES S-box及Sigmoid近似实现。定点PWL有利于同时检验选择、乘加与舍入/饱和，纯LUT路径也可作为较小起点；算法、位宽、误差和L在实施试点前确定，不在本轮编造数值或承诺收益。
2. **更多内部结构的第二批**：宽加法、商余、binary32乘法内部组，以及与原有限位函数等价的更多S-box/Sigmoid结构候选。每类单列生成、正确性、内部寄存器和模型覆盖证据，不能以其他类别通过替代。
3. **数值与架构的第三批**：浮点加除/exp等、误差约束下的算法联合选择、控制反馈/资源共享/轮次展开和握手转换。架构变换使用独立的时序/吞吐协议，不纳入首版固定L/II的纯DAG调度结论。

**AES试点边界。** 先定义无状态的128位普通加密轮：SubBytes→ShiftRows→MixColumns→AddRoundKey，以128位state和显式128位round_key为输入，固定字节顺序。轮密钥随事务对齐，初版试点不含密钥扩展、初始加密前加钥、末轮省略MixColumns的变体及轮次控制；如后续增加，各另列语义/结构版本。单轮不等于完整AES加密。

仓库已有 `example/aes1/`、`regression/aes1/` 和 `rtlzz/testv2/example/aes.logic.cpp`，采用状态、数据/密钥寄存器和握手的迭代实现。可复用其来源及参考思路，但现有功能生成/回归不证明本计划C/D已自动改写迭代架构。本轮只读源码，不重新宣称这些用例通过。若全轮已由用户静态展开成无状态组合DAG，可在满足前端、规模、组及模型条件后按同一框架调度；从迭代模块自动推导这种展开则是另一项能力。

**Sigmoid试点边界。** 先定义固定格式、输入范围和固定参数的有限位函数，冻结LUT或PWL及饱和/舍入顺序；用已登记语义API或受支持库函数输出真实DAG。纯LUT可以用显式索引/映射处理输入符号；有符号算术不是每个LUT方案的必需条件，但其数值解码仍须明确。PWL/多项式涉及的有符号乘加、算术移位及饱和必须先验证，不能直接套用无符号Mul模板。浮点输入或源码 `1/(1+exp(-x))` 需要额外前端/数值实现，不因名字叫Sigmoid便自动转成近似表。

应用评价中的C/D仍共用同一语义和结构候选集，边界由调度器选择。已经内联成细粒度节点的图，B也可以在其节点之间流水化；仅在helper内出现寄存器不自动算C新增了内部拆分能力。须报告输入图、B的原子边界和C新增的真实展开/合法边界；若B/C边界相同，明确该试点只证明DAG调度/模型适用性，不用于量化“允许拆分”的收益。

## 7. 代价、训练、位置选择与资源

### 7.1 B/C：简单静态权重表

现行模式命名 `fixed-op-width-v1`，在新实验中替代旧 `simple-cost-v1.1`；旧计费只在尚未迁移的步骤中临时使用，迁移后退出活动路径，原规则限定在冻结快照中追溯。固定权重的含义是：类别、位宽档及表值在实验前固定，不读平台实测；并非所有位宽必须等价。四个平台 B/C 使用同一张表，不设工艺专属缩放系数。

以下为本计划给出的**首版实现表**，在步骤二补充验收中落实为独立配置并冻结。只允许基于语义、规范化一致性和实现缺陷修订，不根据已知 ASAP7 的选中结果或收益调表。后续如研究其他权重，另列敏感性扩展，不替换主表。

| 输入计费位宽档 | 1 | 2 | 4 | 8 | 16 | 32 | 64 | 128 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| Mul 时延代理 d | 1 | 1 | 2 | 4 | 8 | 16 | 32 | 64 |
| Mul 组合成本代理 a | 1 | 1 | 2 | 4 | 8 | 16 | 32 | 64 |
| Div、Mod 时延代理 d | 2 | 4 | 8 | 16 | 32 | 64 | 128 | 256 |
| Div、Mod 组合成本代理 a | 2 | 4 | 8 | 16 | 32 | 64 | 128 | 256 |

时延代理 `delay_weight=d` 与组合成本代理 `comb_weight=a` 是两个独立字段；首版表值相同只是配置选择，不能在实现或报告中合成一个字段。其余类别的d/a首版均按简单常数：Add/Sub/AddCarry/Negate/Compare、逐位逻辑、二选一 Mux 与归约为1；动态移位、动态位选/切片/写入为2；纯赋值、常量切片/拼接、扩展/截断和实际为连线的常量移位为0。二者没有 ps 或 µm² 含义，组合代理不是物理面积模型。未知操作必须显式降低或拒绝，不能沿用旧模式的默认1。

计费与规范化约定：

- 成本阶段仍为组合 BEOPT、共同区域处理、候选展开和冻结清理之后，调度/寄存器物化之前。原始和展开候选采用同一规范化版本。
- Mul/Div/Mod 以输入数据的语义位宽确定档位。剥离已验证的无符号零扩展，或读取被保留的宽度来源，防止 32×32→64 因前端把操作数扩成 64 位而被错收为 64×64。等价表示须收费相同；没有可靠证明时拒绝该匹配或保守使用类型宽度并标明，不能凭测试值缩宽。
- 两个 Mul 输入宽度不同时取较大者；非表内输入宽度向上取最邻近档。超出 128 位的算术输入不在当前乘除表覆盖内；256/257 位加法和连线等中间操作按其类别规则支持。不能把中间结果宽度误当乘数宽度。
- 完整乘积和低位乘积可暂收相同权重，明确这是简单模型限制。结果宽度始终保留在语义和报告中；输出截断不自动改变输入计费宽度。
- Case 保留优先级，Lookup 保留索引可达性和越界语义，再按版本化规则降低为二选一 Mux 图计费。Ite/Case/Lookup 不复用旧面积位宽公式；旧选择节点修正作为历史保留。不得用重排改变优先语义。
- 完整浮点等原子区域的代价来自其规范化内部 DAG 的最长路径及共享节点成本；“不可切分”不等于将全部成员延迟串加。显式共享商余计一次，未共享 Div/Mod 分别计费。
- 纯常量子图不计事务路径延迟及状态。静态 facts 可以支持合法规范化，但不能按观测数据制造免费硬件。

组合代理成本按实际共享节点各计一次，即对互不重复的节点累加a；时延则以d在每级DAG上算最长依赖路径，级内并行部分积的d不能相加。共享跨级数据及valid每保存1位增加1单位状态成本。单候选先在固定L下求得抽象基准T0，再在 `Tmax≤1.05×T0` 内通过合法整组移动减少状态成本；组合图固定时不假称移动减少组合逻辑。

C 在完成合法调度和验证的候选中按 `(最大级抽象代价, 组合代理成本+寄存器位数, 寄存器位数, 寄存器信号数, candidate_id)` 字典序选择。B 使用同一表和调度策略，但关闭操作内部切分。两组都不读取物理周期/最终 PPA 进行重选；抽象时延低不等于已预测满足时钟。

保留“不拆分”且不规定C必须选到拆分。讨论过的“所有位宽的Mul同一个常数”和当前“按位宽分档的固定表”是不同模型，不能互相代用推断。对分档表，四个W/2乘法的线性组合权重总和可能大于一个W乘法，但部分积并行、时延按路径计算，且C首先比较最大级抽象延迟；因此“总组合权重翻倍”不能直接推出C选择不拆分。位宽无关常数是否抑制某个模板，也要结合归约路径、L、边界、状态与排序验证，不能写成普遍结论。至少对大小Mul、Div/Mod、扩展/截断、零成本布线、商余共享及多路选择做结构一致性审计，不预设新表选择结果。

由于历史 PPA 已经可见，不能再宣称新表冻结早于所有物理观察。应记录本轮需求变化、表值的非实测来源、冻结时间和已知历史探针；冻结后不根据新采集数据调参。旧物理误差审计只用于解释旧模型，不充当新表的标定或验收。

#### 7.1.1 计费审计与预声明敏感性诊断

主表数值保持不变。步骤二/五补充一项选择层诊断：在全部五档W的MUL_W、MAC_W上，固定源码及规范化结构候选、合法边界、L/II、调度策略和排序，比较主C的线性乘法组合成本与平方乘法组合成本。原始、half、quarter候选按支持表选取，最多30个结构、两种成本重评；这不是新增正式实验组。

平方诊断只替换Mul的a：以输入计费档位w取 `a_square(w)=w²/64`，32位Mul仍为16，与主表在32位锚定；1/2/4/8/16/32/64/128位对应 `1/64、1/16、1/4、1、4、16、64、256`。所有d、Div/Mod及其他a、每位寄存器成本1均保持不变。该尺度下32位Mul的组合代理与16位寄存器成本相等，仅是预声明的诊断比例，不代表物理面积。按精确有理数比较，不以向上取整暗中换尺度，也不再增加可调缩放系数。

优先复用同一组合法级分配，分别记录最大级抽象代价、共享节点组合成本、数据/valid寄存器位数与状态成本、完整排序键、名次及最终选择是否变化；如重跑调度，保留结构/调度哈希和初始/最终映射，解释是否发生位置变化及原因。先审计并行路径、共享节点、宽度取档和寄存器链，再解释差异；排名不变同样是有效结果。

本诊断优先在模型计算/编译器选择层完成，实际生成、分析、推理和必要功能核对按support计时间，提前纳入当前阶段清单与额度；它不自动增加synth/grt/final，不启动第二套688条PPA矩阵，不替换主C，也不根据C是否拆分或D是否获胜调权重。若后续确需物理对照，另登记有限RTL/约束/阶段清单，按§7.7单独准入和计费。

### 7.2 四平台采样设计

采样的对象是**给定库、目标、边界及流程下的实现**，不是操作固有的一个延迟。四个平台独立建立数据集、独立训练和发布模型，采用统一 schema 和评估脚本。

必需覆盖的原子/复合实现包括：

| 类别 | 位宽与实现变体 | 必须区分的上下文 |
| --- | --- | --- |
| Add/Sub/AddCarry、比较 | 五档输入及实际进位/输出宽度 | 输出截断、进位输入、串行/并行组合 |
| Mul | 五档完整/低位乘积、分块叶乘法、归约组 | 输入/输出宽度、分块/归约版本、尾块和常量特征 |
| Div、Mod、DivRem | 五档动态非恒定除数，完整核及实际已开放组 | 安全包装、共享身份、独立商/余实现 |
| 移位、位逻辑、选择 | 五档数据位宽 | 常量/动态移位、方向、索引范围、Mux/优先选择 |
| binary32 | 完整乘法区域、已开放的子组 | flags、语义/模板版本、串联/旁路上下文 |
| 状态与边界 | 数据/valid、同步复位、使能、共享链 | 寄存器位数、扇出、边界壳、负载与时钟开销 |

“多次实验”首先是覆盖位宽、结构、目标、负载/扇出及组合上下文的不同样本，不是把同一个确定性网表重复运行若干次当成训练规模。重复测量用于稳定性检查，带独立标记且归入同一数据分组。节点没有相应实现特征样本时，不得仅凭操作名字声称覆盖。

先定义各平台参考上下文 `R_p`：ASAP7 可沿用 1500ps 参考点；其余平台根据官方配置和预声明小探针确定合理参考周期并冻结，不能机械使用 500～2000ps。参考周期不是所有正式案例的目标，也不是跨平台相同绝对速度的约束。

采集分三层，按平台及当前获准阶段冻结实际清单，依身份去重并纳入§7.7预算；无需等待其他未就绪平台的全部明细：

1. 在参考上下文覆盖必需操作/位宽/模板，完成单位、标签和容量检查。
2. 在代表性乘法、宽商余、binary32 实现上做少量预声明 ABC/SDC/负载敏感性探测，确定模型的条件特征、采样区间和必要追加样本。
3. 按训练/验证需要采集不同结构和上下文，直到达到已冻结的覆盖清单。参考点、敏感性点、重复及独立测试均分开计数。

500/800/1000/1250/1500/2000ps 是旧 ASAP7 研究的历史点集，不再成为四个平台每种操作的强制网格。目标轴可以采用相对 `R_p` 的点，需在采集协议中固定换算、I/O 规则及 ABC/SDC 是否联动。两轴仍分别记录；若只采集对角线 `ABC=SDC`，模型支持域只能承诺该关系附近经验证的范围，不能据一维区间声称覆盖整个二维矩形。

保留受控探针要求：同结构比较目标时固定 L/II/库/种子/密度/优化，优先复用已实现的检查点；重新综合照实计费，核对网表。I/O 绝对值或比例策略预声明；对已完成物理实现可用共同 SDC 做 STA，以结构、面积和路径指标判断响应，不只看各自 slack。观察相同不生成未测标签，也不否定结构拆分的价值。

### 7.3 标签、模型训练与泛化

数据每行绑定源码/生成参数、结构和调度哈希、完整测量身份、阶段、路径类型、原始报告和状态。时延标签优先取边界壳中的数据路径，并把 clk→Q、setup、uncertainty、时钟/外部 I/O 开销分开；保留 cell/wire、输入到各出口的关系。`minimum_clock_period`、纯组合路径和 ABC 诊断值不可混作同一训练目标。面积标签区分组合、顺序、时钟/物理专用开销，避免将整个边界壳重复计入每个节点。

工具成功而 setup 为负的样本，可以保留完整面积/路径标签并标为时序违约；超时、崩溃、缺报告、未约束或未提取完整的数据不作为零成本样本。失败记录进入覆盖及资源报告，不自动推断域内所有点失败。

模型组织采用两级可解释路线：

- 用综合标签训练操作/区域实现的基础时延和组合成本模型。
- 用 grt 样本训练阶段/组合图的物理修正，特征包含活跃值、寄存器与扇出、阶段结构、节点/连线规模、目标及冻结物理设置。不能把孤立微基准的整段互连开销逐节点串加；若首版只能采用近似局部模型，应明确近似及验证误差。
- 寄存器/控制和时钟开销单独估计；共享链由真实调度图计数。完整模板与内部节点二选一计组合面积，不双计。
- synth/grt 分别训练、分别标记模型与预测阶段。详细布线用于复核，首版不强制训练第三套模型。

首版比较常数/简单线性模型、正则化回归和一种可控制复杂度的树模型。选择依据是验证集误差、排序/可行性表现、推理成本及可解释性，不是正式案例收益。训练时可用位宽、输出宽度、符号、常量特征、操作/模板、扇出/负载、ABC/SDC、阶段图特征；不能使用预测时不可获得的“最终映射单元数”“实际关键路径”等后验特征，除非它们属于单独有成本的测量方法。

扩展到§6.4结构时，特征/支持域需能区分所用有符号语义、常量乘、选择/表规模与内容特征、扇出/负载和阶段组合关系；表/系数内容哈希用于身份追溯，是否能跨内容预测须由实际特征及独立验证决定。GF低层位图可复用已验证位运算模型，定点可复用其合法降低后的整数图，但不能只凭操作名字相同或位宽落在范围内便认定D覆盖。未见过AES/Sigmoid整图本身不必导致拒绝；反之，原子节点均有模型也不保证新阶段拓扑、扇出及交互落在验证域内。用登记的操作/子结构和合成上下文扩域，不把应用评价整图PPA回填训练或调参。

训练数据只来自登记的微基准和合成上下文图。按结构/模板族、位宽与生成家族做分组划分，重复、同源网表及其目标变体放在同一分组；禁止随机拆重复行。每个必需操作都要有足够训练支撑和独立验证/测试结构，划分清单先冻结。可安排留一位宽的域内泛化测试，例如在其他档有训练支撑时检验 64 位；不默认具有超出最大训练宽度的泛化。

正式/保留整图 PPA 不进入训练、模型选择或全局参数调整。保留图可以使用已训练原子操作，但整体结构不得在微基准中逐字复刻；“没见过该整图”与“没见过该位宽/模板”分别说明。首版不承诺未训练平台的零样本迁移。

各平台分别报告：时延/面积的 MAE、相对误差中位数和高分位、最大误差及覆盖分母，另报候选排序、错误可行预测和保守拒绝情况。接近零的标签使用预声明绝对误差尺度，避免 MAPE 失真。质量门槛及误差裕量的制定方法在独立测试前冻结；可用验证集确定保守裕量，不能看测试/主矩阵后追改。模型未达门槛则标为未就绪，不能以“已经训练出文件”代替模型验收；也不预设必须比 C 赢多少案例。

冻结模型包包含：平台/库/流程/阶段身份、feature schema、训练代码、数据与划分哈希、算法/超参数/seed、预处理、单位、模型文件哈希、验证指标、支持域和裕量策略。C++ 与 Python 对同一特征的推理在冻结容差内一致；需要 Python 的推理依赖须显式声明，不能在生产查询时悄悄换实现。

### 7.4 实测、预测和未覆盖状态

旧“目标必须精确命中已测点”的查表协议保留为历史，不适合作为训练模型的全部查询语义。新协议至少区分：

| 状态 | 含义与处理 |
| --- | --- |
| `measured_exact` | 完整测量身份命中，返回原始指标及来源；缓存复用还须匹配实际 RTL/阶段 |
| `predicted_in_domain` | 平台/模板支持，数值和条件关系在验证过的支持域内；返回模型估计、裕量/不确定性及模型版本 |
| `uncovered` | 未支持操作/模板、未训练平台、域外目标/宽度或上下文错配；拒绝正式 D 查询并说明维度 |
| `failed_measurement` | 对应测量失败；不冒充模型预测或零成本，保留阶段和原因 |

模型可以在其已验证域内预测未实测的精确周期，不再强制为每个案例周期逐点补全全部操作；这正是拟合模型的作用。域内不等于独立特征的 min/max 均满足，需包含离散特征、交互关系与训练支撑。域外不得偷偷取最近点、外推或切换到旧表。扩域使用预先登记微基准重新采集、训练并版本化，消耗预算，不用正式整图结果回填。

### 7.5 自动选择寄存器位置

每个合法组 g 的级号 `s(g)∈[0,L-1]` 是调度变量。依赖指向同级或后级，不可切分成员同级；原子区域不能被节点级移动拆开。动态值从生产级到最晚消费级建立一条共享链，多个消费者不逐边重复收费。valid/reset/flags 和旁路与同一事务对齐。

初始可行性放置、阶段代价、整组局部优化和最终校验使用同一组约束及同一成本上下文。组收缩保留成员拓扑、入口到出口路径、多出口活跃值；不能将组的全部节点输出都当跨级状态。保留初始与最终级号、尝试/接受/拒绝原因，即使接受移动数为零也能核验自动放置。

D 的目标周期先转成各路径类型的数据预算：扣除与标签定义不重叠的 clk→Q、setup、不确定度和冻结时钟/互连预留；外部 I/O 路径使用相同 SDC 单独处理。单位全为 ps，不能把完整周期标签再扣一次边界开销。非正预算、缺覆盖、不可放置组须清楚报错。

若保留相对 5% 放宽，路径 p 的上限是 `min(1.05×T0[p], B[p])`，绝不允许超过用户绝对预算 5%。D 模型进入初始调度、每次整组移动及最终检查；采用阶段图物理修正时，移动后必须重算相关阶段，不能只改变末尾评分。预测面积包括实际寄存器链与控制开销，允许时钟预算内减少寄存器或选择原始实现。

保留旧五项组约束验收：初始不拆组、局部移动不拆组、可接受有益整组移动、组内路径与组外多出口/共享状态一致、不可行组定位清楚。再分别在新 C 和各平台 D 下做同结构位置验收：固定结构、分组、L/II，评估至少两种依赖合法级分配，记录各级成本、跨级链、寄存器位数与接受/拒绝。

位置证据必须区分：约束下已评估范围仅一解、存在多解、真实策略在多解中选择。一个可行加一个超限拒绝只说明该范围的位置受约束确定，不证明偏好选择。更宽 cap 的诊断不混入正式策略，枚举器结果不冒充编译器搜索轨迹。改变模型/目标后位置相同是有效结果；不要求制造位置变化，也不由零次移动否定自动调度。

至少为每个平台 D 核验一个固定结构在两种预声明上下文下的查询、预算和调度输入确实更新；可以选出相同位置，但不得复用错平台成本。不同结构的 PPA 差不能单独归因于位置；若量化位置收益，另做同结构物理对照并预留资源。

展开资格、分组合法性、模型覆盖、调度可行性和物化正确性按§5.3–§5.4分阶段核验。可行性与局部移动的拒绝记录使用同一原因码/明细协议；一个超限组、有限搜索未找到解、L下界不满足和实际方案校验错误不能统称“模板不可行”。

### 7.6 C/D 的离线候选选择

两层决策：外层枚举原始实现、分块与已实现分组配置，内层由本组代价自动放置合法组。C/D 采用同一有序结构清单、同一 K 上限、同一语义/优化/合法边界；允许因代价不同而生成不同调度结果。结构候选数、内层位置尝试数及最终送验证的完整实现数分别记录。

D 正式选择时不运行候选 PPA。先拒绝无覆盖、非法、功能或周期不正确的候选；在预测满足目标的合法候选中按 `(预测总面积, 预测最大级延迟, 寄存器位数, candidate_id)` 确定性选择。若声明候选范围内已完成覆盖及规定搜索/评价、无实现错误或调度未决，且无预测可行候选，输出明确 `predicted_infeasible`，其结论限于声明的候选/策略与模型；无覆盖、未找到放置或搜索受限按§5.4/§9.2分别报告，不能统一改名为预测不可行。可以按预先规则生成一个功能正确的最小预测违约诊断实现供最终评价，但不能把它记为成功选择。

入选 RTL 完成功能验证后按共同后端流程评价。实测失败或未满足目标原样保留，**不据最终 PPA 选择第二名**。编译/功能错误不得隐藏；仅在预声明规则下按估计排序选择下一合法实现并计数，不能看 PPA 后再称为功能回退。

`D_feedback` 是扩展方法：同模型与候选范围，但在独立预算中测量若干候选再择优；其结果不替换正式D，也不回填全局训练。C首先按最大级抽象延迟排序；D则先检查预测时钟可行，再优先最小化预测面积。四组主表的C→D因此反映**平台模型、物理预算约束与选择策略共同改变后的整体效果**，不能把全部差异单独归因于模型预测精度。离线D不混入在线反馈，本轮也不为此增设正式组；预测精度在独立模型测试中另报。

## 8. 案例矩阵、目标制定和公平比较

### 8.1 四组定义

| 组别 | 操作内部切分 | 选择依据 | 后端评价的用途 |
| --- | --- | --- | --- |
| A | 关闭 | 原始组合核＋共同边界壳 | 记录原始面积/时序，L通常为1 |
| B | 关闭 | §7.1 静态权重表，固定L的整操作调度 | 仅评价入选结果，不重选 |
| C | 仅开放支持表内的边界 | 与B相同静态表，自动选模板/位置，保留原始实现 | 同上 |
| D | 与C相同的结构和边界范围 | 目标平台独立训练的离线模型及物理预算 | 同上；实测失败不反馈重选 |

每个平台内部四组使用相同源语义、原生发射器、预处理/区域隔离、边界壳、I/O/valid/reset、综合/物理策略及主表阶段。B/C/D 对同一案例 L 相同、目标相同；四个平台使用相同逻辑案例和 L，但目标周期及实际库约束按本平台参考数据制定。B/C 的选择器不使用物理目标，D 使用；这是对照定义的一部分。

B→C解释为统一简单代价下开放内部结构候选的影响。C优先最小化最大级抽象延迟，D在预测满足时钟后优先最小化预测面积；C→D因此是**平台模型、物理预算约束和选择策略的整体效果**，不能将全部差异单独归因于预测精度。C/D也可能改变模板及位置，不能把整体PPA差异只归因于一种变化。未支持的除法/浮点内部边界不算拆分收益。模型精度独立测试，训练一次性成本、推理/搜索成本和最终评价成本单列；本轮不为归因增加正式实验组。

### 8.2 参数化正式案例：32个

下表每个带 W 的家族展开 W=8/16/32/64/128，共六家族×五档=30 个，另加两个浮点案例。每个家族有统一生成器、参考和配置，后端不能将动态输入替换成常量。

| 家族 | 数量 | 功能与结果宽度 | 检验重点 |
| --- | ---: | --- | --- |
| `MUL_W` | 5 | `y=a*b`，完整2W位 | 纯乘法跨尺寸、参数化分块、真正内部寄存器 |
| `MAC_W` | 5 | `y=(a*b+c) mod 2^(2W)`，c为2W位 | 大乘法与后继加法、进位/截断 |
| `DOT2_W` | 5 | `y=a*b+c*d`，两个完整乘积，输出2W+1位 | 并行分支、共享/对齐及宽累加 |
| `UDR_W` | 5 | `defined_udivrem_W(a,d)`，输出q/r各W位 | 动态商余、零除、实际共享身份 |
| `DIVSEL_W` | 5 | `(q,r)=defined_udivrem_W(a,d)`；`y=select ? (q+bias) mod 2^W : bypass` | 长算子、短旁路、Mux及附带r的对齐 |
| `MIX_W` | 5 | u=(a+b)低W位，v=(a-b)低W位；l=安全左移(u,s)，r=安全右移(v,s)；y=((l&mask)\|(r&~mask)) XOR defined_umod_W(a,d)，另输出a<b | 独立取余、加减/逻辑/比较/动态双向移位，防止模型只支持乘除 |
| `F1` | 1 | binary32单次乘法，bits+flags | 浮点区域、特殊值和舍入 |
| `F2` | 1 | binary32两次串联乘法，每次舍入，flags OR | 完整操作边界与长依赖 |

MIX 的输入均显式给定宽度和掩码，s 包含 s=W 及更大的取值；位运算不能被生成器常量化。`defined_umod` 使用同一安全除数包装。UDR 的共享状态由实际图决定，不因同时输出商余就假定有一个共享硬件实现。

| --- | ---: | --- |

### 8.4 L和目标周期

沿用固定延迟原则，默认 `L=max(2,heavy_operation_depth+1)`，heavy 为未展开原始图上的 Mul/Div/Mod/完整浮点等重操作；并行重操作不串加，串联商余/浮点按依赖深度计。MIX 的动态取余计重操作。L由图和规则生成，同一案例四个平台保持一致，不根据某平台D结果调整。

旧周期公式中 `max(max_operation_delay,sum_delay/L)` 会让单个完整重操作的参考延迟成为下界，未必能检验内部拆分在紧目标下的作用。本次版本化改为：

```text
D_ref[p,case] = 从冻结参考微基准映射到原始依赖图的关键组合路径估计
T_target[p,case] = ceil(H_ref[p,case] + (3/2) * D_ref[p,case] / L[case]) ps
```

`H_ref` 是明确边界与时钟/I/O策略下、不与D_ref重复的开销；D_ref取同平台、同阶段、同口径参考标签，在原始图上按最长路径而非把并行支路全加。3/2 是预先给定的目标松弛系数，不从正式/保留PPA调出；单重操作L=2时，目标数据预算约为参考路径的75%，可能不可行，必须保留结果。目标公式不是已实现的时钟保证。

平台参考 R_p 是起点。宽商余若在同一参考设置下无法得到有效标签，可以使用**先声明的按平台/家族/位宽伸缩参考设置**，保留每项 ABC/SDC 身份；不能偷偷放宽失败点再伪装相同条件。当前平台/批次的参考清单和标签完成后，一次计算本批次目标并冻结，不依据模型选择、整图实测或后续补采重算目标；不要求其他平台的参考标签同时完成。

目标规则变更的理由、参考点、H分量及数值写入 `target_rules_v2`。共同公式先全局冻结，目标数值和参考身份在各平台/批次评价前冻结，不必等待全部平台。若早期容量/单位核查发现规则不可执行，先提出技术修订并重算全部受影响案例；已有结果保留版本和失效范围，不能只为消除某组/某案例失败放宽周期。D所需目标须处于其验证支持域，否则先使用登记微基准扩域或明确未覆盖，不能对正式图在线测量后回填模型。

### 8.5 K、详细复核与重复

首版结构配置上限拟定 K=16/案例，C/D使用同一有序截断前清单。各Mul的original/half/quarter组合、多区域候选的枚举顺序及去重规则在执行前冻结。最多K不要求把每个候选物理测量；正式D无搜索PPA调用。候选/组移动超时单列，确定性编译错误不重试，确认属于临时资源/工具中断最多一次且计入预算。

详细复核基准点：每个平台选 `MAC_32、UDR_32、F1` 的A/B/C/D，共 `4×3×4=48` 条。再最多8条覆盖每个平台128位乘法和128位商余，按预声明顺序优先D、再C；未产生合法RTL或流程失败同样保留，不用更有利点替代。此为独立复核表，不替换主表个别指标，也不触发B/C/D重新选优。若实现身份匹配，可复用已完成阶段，但要有实际机制和来源。

先确认固定配置的确定性，再对接近目标、收益很小或种子/线程敏感的点按冻结规则追加重复，保留变化范围及是否影响胜负。重复32条冷链、其中8条详细链是§7.7的容量情景，不等于必须无条件执行；不能假设固定ps噪声底。四平台详细范围若因实测资源需要改变，须在查看主收益前统一修订复核协议和预算，不选择性保留有利复核。

### 9.3 比较与冻结

先验证正确性、L/II和阶段完整性，再判断实测时钟。C/D都可行时比较同口径面积，列绝对/相对差；只有一方可行时报告可行性差，不能把另一方的面积优势记作成功；都不可行时报告违约，不算满足目标的收益。正式与保留、各位宽和各平台逐例报告，不剔除无收益或失败。

先做平台内统计，跨平台仅汇总各自基线归一化量或可行率，并给清楚分母。面积几何平均只在双方均可行的同平台配对集合上计算；没有配对则不制造数值。训练和采样的一次性成本单列，若摊销须说明设计数与方式；不把一次性建库写成免费。

不设“D必须赢C若干例”“128位必须有收益”“目标点必须响应”等完成门槛。需要证明代价模型真正进入拆分及位置决策、训练和比较有效，随后如实解释结果。如果所有D都退化，仍需检查候选/查询/预算链路并报告模型适用性，不能只看可运行就宣称优化目标已经实现。

精度报告与方法效果分开：C→D改变了成本来源、绝对预算及首要排序目标，即使D实测更好，也不能仅由主表认定是预测精度改善所致；精度须由冻结的独立测试给证据。§7.1.1诊断只检查组合代理敏感性，不能当作隔离所有选择策略因素的实验。

案例/方法、静态表、共同特征schema与归一化规则、当前模板和调度策略版本、目标公式、数据划分规则及评价协议先全局冻结；这不要求未就绪平台的拟合参数或未来扩域模板全部实现。模型及其拟合预处理参数、当前数据划分、目标数值和参考身份、资源/复核清单在对应平台/批次执行前冻结；其他平台可未就绪。影响选择或语义的修改产生新版本，逐项重验受影响记录，不能在已看PPA后调权再覆盖原记录。先导模型扩域后重新核对选择/功能/身份；旧PPA只有满足实际复用条件才可进入最终主表，否则重新计费评价。先导保留图PPA不用于后续训练、调参或选模型，保留已观察记录，不宣称最终所有保留结果从未曝光。

### 9.4 按位宽分层的结果、模型与容量报告

五档W均保留参数化、正确性与四平台四组PPA要求，128位不因预计昂贵降为选做。按算术输入W归层，256/257位结果仍属于128位整数层；浮点三例单列binary32，不重复计入32位整数层。每个平台每个整数W有6个正式家族＋2个保留家族，共8例×4组=32条；五层160条加浮点12条=172条，四平台仍为688条。

每个“平台×位宽层×方法”报告：实际周期/数据路径与setup/hold、单元面积与配对收益、功能及主阶段可行率；顺序面积、实际共享寄存器链位数、valid/flags/边界和控制开销；叶命令墙钟/CPU、峰值内存、失败阶段/超时/内存终止及未完成数；同层模型误差、覆盖/未覆盖与预测误判分母。正式和保留分列，阶段已验收和全范围待补分列，不能只汇总一个平均收益掩盖128位失败或未覆盖。

寄存器数量由级分配、跨级活跃值、共享链和截断等实际结果决定，不将某模板部分积的名义总宽度认定为“必须保存512位”。寄存器/控制是否主导面积须有同口径分解；128位耗时是否为32位的某个倍数、是否拥塞，均由§7.8分层容量探针确定，不预写5–20倍等比例。阶段失败保留正确分母；尚未实现功能不能只填一条PPA失败就算完成支持。
