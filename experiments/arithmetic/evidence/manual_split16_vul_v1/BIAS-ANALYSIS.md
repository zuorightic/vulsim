# D为何没有选择这份手写split16实现

本次只读诊断复用原三档物理快照，没有新增综合或布局布线，没有修改已发布模型、预留或选择器。所有数值已用于诊断，不再声称是后继模型的独立测试。

原D搜索包含12个original、15个16位half及17个8位quarter，共44个合法放置。用户指定的“4个16×16在第一级、移位归约及加c在第二级”确实在其中，标识为`candidate/half/view5`。完整覆盖时，存在预测可行解就选最小总面积；全部违约就选最小最大预测违约，面积打破并列。逐候选排序已只读复算一致。

1500ps下，original/view1的预测面积761.772um²、最大周期要求1349.670ps（含单次50ps阶段预留）；half/view5为906.346um²／1540.264ps，被判违约40.264ps。half/view4把首层两个归约AddCarry也前移，第一级／第二级点预测1387.382／1105.798ps，含预留最大1437.382ps，预测可行，但面积889.712um²更大，所以仍选original。

即使采用手写版本的实测价格，1500ps下手写830.156um²仍大于原D761.134um²，两者都满足目标。现行“可行后最小面积”的目标函数不会因手写版本更快而选它。需要优先修正的是500／1000ps全部违约时的候选实现与时序排序，而非改变目标函数来制造1500ps收益。

## 已取得的综合证据与尚未分离的因素

手写RTL三档`synth.log`均在ALUMACC阶段把4个Add模型合并为同一个`$macc`，并与4个部分积乘法合计生成5个`$macc`；maccmap随后映射多操作数归约。1500ps日志约705–713行直接记录三次`merging ... into $190`。加c参与同一归约，不再按源级三层二输入进位传播加法逐层实现。

现行half模板把乘法部分积的3个AddCarry及最终加c分别作为算术节点、分别保留算子层次；G=0的DAG预测沿路径累加各节点独立最大延迟。加法树的独立最大值相加本身可能偏保守，保留不同算子边界还限制跨节点压缩／逻辑重写。本次手写代码同时改变了加法网络的实现边界，部分中间位宽／截断表达也有差异。当前已证明联合综合发生，尚未测量原保层次half/view5，因此无法仅用这三个点精确分摊“映射限制”“独立最大值相加”“基础节点函数”各自占多少ps。

## 通用修正路线

1. **先做同图、同放置的有限边界对照。** 复用同一half/view5图及同一寄存器、reset、valid、T，比较原各Add独立保层次与保留乘法边界、允许同级归约Add联合优化两种策略。重点在1000ps等全部违约目标下核对两级与排序，不能先在全部44候选上跑后端，也不能用手写raw结果给原half填价。
2. **把可融合的加法归约作为通用实现单元。** 每次placement形成后，识别同一级、无内部寄存器、无必须保留中间消费者的加法／常量移位／补零／合法截断子图，将c等同级加数一并纳入。保留归约区域外边界，区域内部允许后端联合综合；采样、D发射和最终评价采用同一版本的边界策略。它是通用图规则，不按MAC、half、候选编号或精确T分支。
3. **按真实实现域计价。** 继续复用已发布Mul、未融合二输入Add和S。对融合归约，用可在D计算的参数函数预测整块时延和唯一组合面积：输出位宽／截断、各加数的有效位位置、逐列操作数高度或其统计、压缩深度／进位跨度、负载／capture及数值T。对一个融合区域只计一次，不能再累加内部Add的旧独立最大值和面积。该函数可作为Add算法变体或组合提供者内部的归约函数，不要求另造一套复杂G回归器。
4. **S与G保持明确责任。** S继续处理真实FF／控制／边界；DAG在未融合节点及融合区域之间做串联、并行和共享计数。先以零附加残差验证，剩余稳定误差再由通用G特征修正。跨算子融合不能用一个与图无关的负G常数掩盖；也不优先重训整套S。
5. **后继采样和独立验收。** 仅针对新增归约域选少量代表性2–5加数、不同有效位分布／宽度／截断／负载／T，使用区域输出最大延迟和独占面积标签。现有三个手写点保持已消费诊断职责；另登记未见连接／位宽的验证与独立职责。接口、参数、支持／拒绝和选择器冻结后再评价，不逐视图存价，不回填旧ABCD测试结论。

这轮应保持现行面积优先／违约后备规则。目标是让D能生成并正确计价后端实际支持的归约电路；在1000ps等目标下识别更接近目标的方案，在1500ps等已有可行解时仍按总面积选择。
