# 精确分析文件v2

此协议用于步骤五的位置与敏感性审计，机器声明见[exact_analysis_v2.json](configs/exact_analysis_v2.json)。数值编解码为`exact_analysis.encode/decode`，排序键通过`score_key`读取。分析文件不是步骤七的训练标签/特征，也不是步骤八生产输入；后续消费者必须显式选择协议版本，核对身份后才能复用，不能自行猜字段含义。

成本、时延、cap和评分中的精确成本使用约分后的结构化有理数：`{"numerator": 1, "denominator": 64}`。分母为正整数，分子为整数，零唯一编码为0/1。布尔、小数、字符串、非法分母和非约分对象被拒绝。内部以Fraction比较，序列化往返不变值；不得比较JSON对象或字符串的词典序，也不统一转成浮点。

位宽、L/II、stage index、rank、候选/配置数、寄存器位数/数量使用JSON integer，布尔、小数和数字字符串均不接受。候选ID保持字符串。score是有名字段对象，按冻结C元组的顺序解析为数值键。位置cap是否满足使用现有生产调度的`float(recomputed_delay) <= report.pipeline.allowed_delay`比较；有理数编码不会暗中改变该生产规则。

位置报告v2同时保存图/组/L/II/成本查询上下文、声明的枚举范围、重新计算的可行标志、生产级号图及其成本，和枚举范围内等时延/等组合成本的最小状态比较。当前10个依赖合法位置中4个可行，寄存器位数130/144/162/146，生产采用130；这不是完整位置空间的全局最优证明。外层结构选择仍按冻结正式C键独立核验，生产整组局部优化算法未改。

原`mul-position`/`mul-comb-sensitivity-v1`文件保留原字节，仅由其精确冻结分析器在历史路径读取；当前输出和类型校验用v2，不提供默默强转的公共兼容模式。历史原图由读取器重建后送入加强的C++入口；这与旧v1分析兼容读取是两项不同的核验。
