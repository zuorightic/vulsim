# 第一章：局部预算与等效训练周期驱动的九例ABCD规划

<a id="local-request-baseline"></a>

## 1.1 起点、问题与目标

当前代码及已有后端结果以v10为基线。共同组件模型身份为`W345-transition-incidence-functions-v10`，实际完整诊断评分身份为`workload-v10-complete-diagnostic-v1`；组件冻结模型SHA256为`a1466f0272b55bd20358ea9e3beb84844db8fe8fefe4152e0478224d8f13243d`。主入口、公共所有者、状态物化、拆分候选、RTL和已有ABCD实验基础继续复用。

v10给算子／G模型传入全局请求T作为原流程上下文，并沿DAG累计预测时延；它已有完整阶段检查，但没有联合优化各算子的局部请求。小算子采样时的T约束采样外壳中的路径；大模块的同级路径可能串联乘法、加法和其他逻辑，因此整级T并不是其中每个小算子各自可用的时间。预算进入宽松区后继续放宽，也可能不再降低面积。合理比较拆分粒度，需要同时考虑候选结构、流水位置、局部时间分配及其面积—时延响应。

**最终目标：完成九个案例的A／B／C／D对比；按2026-11-16用户追加要求，现行矩阵为§1.9.6的每例两种L、37组T／L及148条主方法，原19组／76条身份保留。D对每个候选先分配算子本体预算，再换算等效训练T并实际调用共享模型，在保持全局T、L、II及功能语义的条件下，寻找满足完整时序且总面积尽可能小的方案。** 若已完整评估的有价候选均不满足T，选择完整时序违约最小、再按面积与稳定规则决胜的后备，明确标记`target_unmet`；缺价另报`cost_uncovered`。预算可分配、等效T转换、模型精度、目标满足和实际PPA改善分别验收。

MAC32先形成软件预算、等效T、完整计价、RTL和ABCD评价闭环，再复用到Add512／Mul128、Dot16／Horner64及其余模算／重组案例。MAC32是实施顺序中的先导，九例完整对比才是本轮终点；不能以单例成功或1034个既有候选的软件重新评分代替最终交付。九例矩阵与各版本定义见§1.9，不把旧W1—W8整套排程重新作为前置。

## 1.2 全局时钟、本体预算与等效训练周期

| 量 | 本轮含义 | 用途 |
| --- | --- | --- |
| `T_clk` | 用户给定的完整设计目标周期，每个流水级分别受其约束 | 完整数据／控制路径检查、S／shared时钟上下文和最终评价 |
| `L` | 固定流水级数，包含原合同的输出capture；服务输入偏移另列 | 约束寄存器位置和状态生命周期；不把T再除以L |
| `a_v / r_v` | 当前候选下，节点输入的最早到达与输出最迟要求 | 沿同级DAG正向／反向传播，处理共享、多消费者和多capture |
| `w_v` | 由当前到达／要求推得的局部窗口 | 作为分配参考；各节点窗口不能直接视为彼此独立、可同时用满的预算 |
| `b_v` | 联合分配给唯一算子／G所有者的本体时间预算 | 约束该所有者内部组合逻辑，不含虚拟采样外壳的寄存器／外部边界 |
| `T_char / T_flow` | 原组件采集时钟／实际整机后端时钟 | 审计原模型T的含义；整机实际周期仍为T_clk |
| `H_char,v` | 采样路径上不属于当前算子本体或其他算术所有者的时间消耗 | 由冻结的采样合同、S／边界函数或相容离线数据估计，用于换算，不在实际整机中逐节点加价 |
| `D_other,char,v` | 采样外壳中其他算术逻辑占用的时间 | 仅在外壳包含消费者等其他算术时使用；不能误算作当前算子本体 |
| `B_char,v(T, x_v)` | 原采样外壳在T和上下文x_v下留给当前所有者的有效本体窗口 | 建立旧训练周期与局部本体预算的数值对应 |
| `T_eq,v` | 由B_char,v(T_eq,v, x_v)≈b_v求得的等效训练周期 | 与旧模型训练T同义，不是大模块新增的局部时钟 |
| `tau_v` | 模型最终实际消费的等效训练周期 | 默认等于T_eq,v；必要量化后记录实际值、窗口残差和原因，通常不等于b_v |

本轮固定语义链为`T_clk／实际路径 → b_v → T_eq,v → tau_v → (d_hat_v, A_hat_v)`。路径分配使用b_v，原共享函数的T输入使用tau_v，最后用模型返回的本体延迟d_hat_v重算整体。若用户界面另接受“含采样边界的局部周期”，必须显式换算成本体预算；实现内部不让同一个字段兼任这两种含义。

模型查询上下文与实际执行上下文分别记录。旧Query若要求`target_period_ps == abc_target_ps`，适配层可将两者一致设为等效采样请求tau_v，并在外层保留实际T_clk及转换收据；该查询描述的是等效采样条件，不能由此声称实际后端已经为该模块设置相同ABC目标。全局物理环境若仍有独立影响，需以独立上下文字段和相容性证据表达。

## 1.3 按实际路径联合分配时间

给定候选结构和逻辑级放置，提取唯一所有者DAG、寄存器切面、capture、连线、状态边界与独立控制路径。每条级内路径p满足：

`sum(v in p) b_v + H_p + W_p + R_p <= alpha_p * T_clk`

H为唯一的数据launch／capture及相关边界，W为有明确归属的连线，R为一次性裕量；alpha仅来自原I/O／路径约束。S拥有的完整valid／enable／保持等控制检查单独验证，不能把整条控制延迟扣到每个算子上，也不能用数据预算守恒代替控制时序检查。

例如，32×32拆分的示意候选有两级流水，T_clk=750ps，其中一级包含“8×8部分积→固定移位→加法”。若该级某路径的实际边界／连线／裕量合计150ps，本体可用窗口为600ps；可先给乘法300ps、加法200ps，余100ps保留为松弛或供其他逻辑分配。若相应采样外壳的边界估计分别为80ps和60ps，且没有其他算术，则等效训练周期为380ps和260ps。上述边界数值均为算法示意，不是实测标签；两级也不是把现有MAC32正式L=3改成L=2。

两个并行支路可以各自使用相应路径窗口；若多个8×8部分积并行，不按乘法器数量再等分，也不把它们的预算串联相加。共享节点只有一份本体预算，并同时满足各后继／capture的最紧约束。编译期固定移位通常归位映射和连线，保留其对结果形状、负载、后继加法及布线的影响；动态移位若生成电路，纳入有价所有者或显式缺价。

分配不是T／L、T／节点数或固定等分，也不能将每个节点独立算出的最宽窗口同时用满。参考预测可用于初始化权重，但不能因旧预测超周期就认定所有实现都无解；仍需允许在正常正预算下请求更快实现。非正窗口及真实边界冲突要显式诊断，不代入log／倒数函数。

首版按“提取每级所有者DAG及capture→由参考预测形成分配权重→在全部路径约束下生成一份联合可行的正预算”初始化。串联、并行、共享和多个capture共同求解，允许保留未用松弛。参考模型只提供权重，不能把其已有时延当作所有实现的不可突破下界。后续时间转移和反馈见§1.5。

## 1.4 采样边界换算、模型复用与实现语义

### 1.4.1 先核对原采样T与输出标签

逐类核对原RTL外壳、SDC／ABC请求、launch／capture、消费者、标签端点及计价所有者，形成可审查的合同。算子模型输出是冻结流程下的内部延迟和组合面积；内部延迟与整机完整最小时钟分开。纯单算子外壳与带消费者外壳分别解释，同类算子仍共用函数与参数，不按案例或实例建立专属换算表。

### 1.4.2 从本体预算求等效训练T

对采样中经过当前所有者的受检路径p，定义：

`B_char,v,p(T, x_v) = alpha_char,p * T - H_char,v,p(T, x_v) - D_other,char,v,p(T, x_v)`

有多个相关端点时，以它们共同给出的最紧本体窗口构造B_char,v；若原采样协议需要更细的端点表达，则保留逐端点约束。alpha_char来自原采样I/O／路径合同。H_char只含当前本体及其他算术以外的净时间责任；算子内部连线已属于本体标签，不能再扣一次。D_other,char只含真实采样消费者等其他算术，使用相容的冻结预测／离线函数估计，不能读取待选应用的后端结果。

软件求解`B_char,v(T_eq,v, x_v)≈b_v`。仅在单算子外壳、alpha_char=1且边界可近似固定时，简化为`T_eq,v=b_v+H_char,v`。带消费者、随T变化的边界或比例I/O必须使用完整关系，不能一律补一个常数。换算所需的边界估计优先复用相容S／采样数据；缺少可辨识信息时明确登记换算缺口，不能凭空指定H_char。

一维反解使用确定性的有限扫描／区间细化，预先登记次数上限、步幅和残差容限。不假定窗口函数处处单调；平台期／非单调可能给出多个近似解，保留有限候选交由完整预测比较。无相容解、非正窗口和量化后残差超限均显式报告，不静默把T_eq设为b_v或T_clk，也不把转换失败直接当作已证明物理无解。极端请求／完整适用范围策略继续暂缓，先解决正常请求下的转换。

模型调用收据逐所有者记录`b_v、采样合同／边界来源、T_eq,v、tau_v、B_char,v(tau_v,x_v)、转换残差、d_hat_v、A_hat_v`及图／位置／模型身份。采样边界只用于换算；组合计价时只计算实际大模块中的边界和S一次，不能为每个节点加入一套虚拟采样寄存器或面积。

### 1.4.3 实际调用共享函数并验证复用

每类算术结构使用共享函数：

`(d_hat_v, A_hat_v) = f_type(x_v, tau_v; frozen_flow)`

x包含原有运算语义、数值位宽、结果形状、已知位、carry、负载和真实消费者等特征。同种结构不同位宽共用参数；不能按案例、实例、精确形状或精确预算查价。tau是转换后的等效训练周期，d_hat是预测本体延迟，二者及本体预算b_v分别记录。局部请求是否满足用d_hat与b_v比较，不能把d_hat改写成b_v或tau来制造通过。

优先保持已有共享函数及参数，通过等效T适配复用；先在固定结构／位置上比较“原全局T输入”和“本体预算转换后的输入”，再以相容的离线串并联组合验证预测误差与排序。软件代入正确、有效窗口相近和物理精度通过是三项不同结论。若驱动／负载、全局物理环境或原T同时改变SDC／ABC造成系统偏差，先定位原因，再对同类共享换算／响应函数补特征或有限校准，保留原参数回归和失败，不能仅凭转换定义宣称原精度已继承。

本轮先实现软件预算与等效T查询，不将逐模块独立ABC设为前置条件。保持当前整机流程时，应以相容组合验证检查这种复用是否能预测嵌入后的实际实现；预算与预测变化不能自动视为电路已经变化。用于最终D排序的响应必须与所选RTL／流程具有经验证的对应关系。仅在明确缺口要求新增结构选项或后端约束时再登记新方案，将模型、RTL／流程与评价身份一起冻结并核验工具消费；不以修改ABC命令或清单数值一致代替精度／效果验证。

预算响应允许平台期和局部非单调，不强制“越紧越快、面积越大”。先比较已有模型在正常请求下的表现，优先复用相容组件数据；仅对明确缺口登记有限补采。本轮暂缓极端请求／适用范围策略，先解决实际预算分配与模型输入语义。实测网表、slew、单元数、坐标及slack只用于离线建模／归因，不能成为在线D必须调用后端才能得到的输入。

G融合区域采用与其自身采样合同相容的同类转换，只分配和计价一次，内部Add不重复拥有预算或价格。当前G负责归约区域，不自动覆盖全部区域间拼接；区域间连线和其他功能逻辑保留独立责任。S／shared按真实状态与更新后的功能面积重算，保留全局T及独立控制责任。

## 1.5 预算、拆分与寄存器位置的联合选择

对每个候选执行“状态／所有者提取→本体预算联合分配→采样窗口反解等效T→实际共享模型查询→S／shared更新→完整路径重算”。按实际边界检查全部数据、独立控制及接口路径；采样H_char不在此重复加入。初始化、反解、预算调整和寄存器位置搜索分别有次数上限，搜索步幅、容差及稳定规则在首版批量评分前写入配置。

同一结构与位置下，从联合可行初值出发，有限尝试沿相关路径转移预算或使用未分配松弛。每次变更重新反解T_eq并查询模型，比较完整违约和总面积；优先探索可缓解关键路径或释放更多面积的调整，小算子进入平台区后不继续机械分配时间。共享节点预算变更必须检查所有后继／capture，不在一条路径上改善而破坏另一条。记录每轮预算、转换、模型价格、完整评分及接受／拒绝原因，保存已完整评分的最好方案。

随后将完整路径压力用于生成有限的新拆分与寄存器位置提案，例如移动合法切面、改变乘法块宽／加法limb宽、调整归约位置。每个新提案重新执行状态物化、所有者提取、预算分配、等效T转换和完整计价；不能沿用旧切面的请求或只在旧赢家上补预算。先固定候选集隔离输入转换的影响，再比较引导搜索的增量效果，并保持同策略归因使用相同搜索预算。

预算分配后，用模型返回的d_hat重新沿全部受检路径和独立控制检查。`d_hat_v > b_v`保留为局部请求未满足诊断；是否满足全局目标仍由完整重算决定。固定点、循环、无相容转换、缺价、无改善或触限分别停止并报告；有价不可行与无法完整计价分开。所选本体预算、等效T、实际查询、价格与RTL／实现身份必须来自同一个已评估方案，不能混用最后一轮预算和较早轮价格。

产物身份同时绑定`图／位置／状态、T_clk、预算向量、等效T向量、转换合同、模型、RTL及实现流程`。RTL字节相同可以复用功能仿真收据，但不同目标／预算的owners、state及查询收据必须分别保存并校验，修正现有按RTL哈希复用目录时可能保留较早T元数据的问题。

目标函数包含唯一算子／G、寄存器／S和shared总面积。宽松目标下，如果粗结构满足T且总面积更低，应允许少拆分甚至保留原始大算子；紧目标下再比较更细拆分与流水平衡。不能预先要求D总选最细粒度，也不能为获得更高频率而在已经满足目标后忽略面积。

### 1.9.2 冻结、对照和交付完成标准

每个目标在读取新应用PPA前冻结数学源、A／B／C／D、模型／转换函数、候选语法、搜索配置和RTL／实现流程。D的候选生成、预算、转换和排序只使用软件可得信息，最终后端只评价冻结结果。最终九例主表采用同一发布版本的共享函数／参数、转换和选择器；若先导后修改了这些身份，早期案例须在共同版本下重新预测、冻结并按实现身份决定能否继承评价。
