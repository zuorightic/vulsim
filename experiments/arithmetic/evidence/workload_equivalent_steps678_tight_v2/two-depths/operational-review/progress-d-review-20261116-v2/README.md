## 新发现一：细拆分的常零位进入了状态计价

这是本轮相较上一轮“状态规模很大”进一步确认的具体缺陷。独立只读位分析发现，Mul128 L4两个目标所选4位块D中，原state投影把81,656位计为数据变量位，其中至少69,752位恒零且复位兼容，约占85.42%；扣除这些可证明的常零位后剩11,904位。该数字包括原state范围内的内部状态及显式输出捕获，不包括额外的输入服务外壳。

| Mul128 L4的状态级 | 原变量位 | 可证明常零且复位兼容的位 | 扣除后的保守变量位 |
| --- | ---: | ---: | ---: |
| 第1级 | 69120 | 62976 | 6144 |
| 第2级 | 10624 | 6272 | 4352 |
| 第3级 | 1656 | 504 | 1152 |
| 第4级／输出捕获 | 256 | 0 | 256 |
| 合计 | 81656 | 69752 | 11904 |

具体例子是图节点4111：

```text
(A[3:0] * B[11:8] << 8) + (A[3:0] * B[15:12] << 12)
```

该节点声明21位，原`variable_mask`把21位全部计为变量。低8位必为零；最大值979200，小于2^20，最高位也必为零，因此至少9位恒零。枚举全部12个相关输入位、4096种取值，得到常零掩码`0x1000ff`，与独立分析相同。再对完整7176节点乘法图使用64组边界／确定性随机输入，核对459264个节点值与全部推导的位掩码／上界一致，完整输出均等于Python 128×128整数乘法。

分析还在其他已冻结D中发现较小影响：

| D实现 | 原数据变量位 | 新确认常零位 | 扣除后 |
| --- | ---: | ---: | ---: |
| MAC32 L3/T500、750 | 928 | 64 | 864 |
| Dot16 L5/T700、850 | 14314 | 608 | 13706 |
| Barrett64 L8/T900、1100 | 2954 | 6 | 2948 |
| Mul128 L4/T600、750 | 81656 | 69752 | 11904 |

其他23份D本次分析没有新增常零位；不代表已完成所有位需求和相关性分析。所有计入的新增常零位复位值均为零，合法写入值恒零、停顿保持零，可按复位／写使能协议归纳。独立分析对不支持的运算保留未知，只使用原有事实，不冒进推断。

根因链条已核对：

1. `rtlzz/src/backend/mul_split.cpp`按部分积移位后做成对二叉归约；每次加法保守增宽一位，最后才截取目标结果。**它是二叉树，没有发现串行左折叠求和的问题。** 低位移位零和部分高位范围界在中间结果中大量出现。
2. `rtlzz/src/backend/beir.cpp:1002`对非常量ADC主要只按操作数最高可能位计算高位零，没有传播ADC的低位常零，也没有利用更精确的数值上界。原图节点4111的known-zero为零。
3. `rtlzz/src/backend/arithmetic_state.cpp:16`只按现有known-zero/known-one生成变量位掩码；`workload_diagnostic.py:268`直接把这些变量位交给stage_words、S面积、控制sink规模及shared总FF特征。缺失事实因此进入实际模型查询，而非仅影响展示。

这会扭曲拆分结构和寄存器位置的面积／控制代价。它不是RTL算术功能错误，也不能直接说后端多用了69,752个触发器：Yosys可消除常零位。这里已证明的是软件变量位和状态特征偏大，没有执行修改后的完整评分或物理实现，不能给出修正后面积、时序或新的赢家。

建议在独立后继版本先补ADC逐位进位事实与安全范围界，统一需求位、算子查询及state/S/shared的掩码；重建状态与负载后再分配预算和优化位置。该修复应以通用算术规则实施，不按本次Mul结果单独调价格。要保留复位、停顿及跨级对齐验证。

证据：[独立分析脚本](known_bit_audit.py)、[31份D的逐项结果与枚举收据](known-bit-audit.json)。

## 新发现二：Horner L4/T1900出现预测可行性排序反转

| 方法 | D共同池预测Tmin ps | 共同池预测面积µm² | 预测达1900ps | 实测Tmin ps | 实测面积µm² |
| --- | ---: | ---: | --- | ---: | ---: |
| B，原子乘法及其既有位置 | 1925.458 | 4675.901 | 否 | 1889.954 | 4643.861 |
| D，32位块乘法 | 1813.151 | 4778.786 | 是 | 1897.885 | 4941.031 |

B的同RTL候选已在D的共同池中，不是漏了B。模型将B误判为违约，按“先可行，再最小面积”的既定规则选择D；本次实际B也达标，比D快7.931ps、面积少297.170µm²，D面积约高6.40%。因此，在该次冻结实测中D被B同时压过。没有重复测量的噪声区间，不能据单次7.9ps差值声称稳定频率差。

这暴露边界附近可行性误差对选择的影响；单个算子、边界、G和整体重映射都可能参与，不能仅凭此点归因给乘法模型。建议保留预测可行边界附近的时延—面积Pareto候选，先做独立组件／组合响应验证和敏感性审查；若改变可行性余量或后端候选验证规则，应另冻结后继协议，不把本点PPA回流改价。
