# 步骤五：无符号乘法自动拆分与分组调度 v1

本版完成独立 RTLzz 组合核上的第一个固定 L 优化闭环。输入源码只有 `y=a*b`；编译配置选择候选，BEIR 展开器产生四个部分积和归约结构，调度器决定合法组的流水级，既有原生发射器生成 RTL。没有手工修改候选 RTL，也没有根据 PPA 调整 B/C 解析公式。

## 接入接口与范围

`rtlzz::CompileOptions` 增加 `use_simple_cost` 和 `arithmetic_candidate`；内部 `PipelineConfig`/`pipeline::Options` 传递同一配置。`original` 保留原图；`mul32_split16` 选择本模板。公开编译 API 和 PipelineV2 入口均有回归。当前没有新增 `vulrtlgen` 命令行选择开关，VUL 的既有默认编译行为由兼容回归保护；主矩阵的驱动接入仍在后续工作中。

模板只处理未被已有区域拥有、保留完整 64 位乘积、无符号 32×32 的 Mul。正常 BEOPT 会把乘数零扩展到 64 位；只有静态事实证明所有 32 位以上的位为零，才接受这种规范化表达。32 位以下的乘数、截断结果、符号乘法和未证明为零的高位不自动套用本模板。没有合适节点时明确拒绝该候选，不能把未展开图报告为已拆分。浮点区域内的乘法不单独拆出，也不产生重叠区域。

S11 为原始乘法登记 `function/mul/ordinal` 身份，原有组合优化后由 Mul 节点保留的 origin 建立区域。这是本版操作出现顺序的稳定身份，不承诺不同源码修改之间 ordinal 不变；缓存仍必须包含源码和候选配置哈希。区域的操作、语义、模板、隔离和切分版本均进入报告。

整数模板的共享策略记录为 `post-BEOPT-Mul-unique-members-DCE-facts-v1`：共同 BEOPT 先处理原始整数图，然后每个仍存在的 Mul 独立展开出新成员，后续只执行边界安全清理。浮点继续使用 `semantic-marker-and-isolated-BEOPT-v1`。两者按各自适用范围统一用于同类案例的候选，不能把整数的后置建区描述为浮点的前置 marker 隔离路线。

## 模板与合法边界

令 `B=2^16`，`a=a1*B+a0`、`b=b1*B+b0`。生成：

```
p0=a0*b0; p1=a0*b1; p2=a1*b0; p3=a1*b1
mid=(p0 >> 16)+p1+p2                 // 34 位容器，保留两次进位
hi=p3+(mid >> 16)                   // 33 位容器
y=Concat(hi[31:0],mid[15:0],p0[15:0])
```

三个组分别包含部分积及 p0 切片、mid 归约、hi 归约及最终拼接。组必须非空、不重叠、完整覆盖区域成员；原图、区域收缩图和组收缩图均须无环。组内不能插寄存器，组间按真实消费者和共享延迟链计寄存器。模板后的清理限定为 DCE 与静态事实分析；通用 BEOPT 会拒绝已声明切分的图，以免悄悄破坏边界。

调度在初始放置、阶段路径计算、寄存器成本、整组移动及最终校验中使用同一分组。组内延迟按 DAG 最长路径计算，四个并行 Mul 不相加。`pipeline::feasibleSchedule` 使用同一放置实现，失败诊断包含区域/组号、级数、允许级区间、cap 和观察到的到达代价。

寄存器物化后，`internal_registers` 单独记录合法内部边界上的状态节点，不改变原组合成员或切分组。校验器同时核对原始与物化图的区域数量、身份、成员、出口、切分组、内部寄存器归属、寄存器来源及级间对齐。不能通过清空区域元数据绕过检查。

## 简单代价与选择

C++ 适配 `simple-cost-v1.1/effective-width-v2`，冻结的 Python 公式及其 12 个 B/C 文件保持不变。适配器使用静态有效位宽，选择节点保留输出类型位宽；条件、索引、进位按角色处理。Lookup 使用原生发射器已有的显式低位索引截断语义，保守计算可达项，不按表值相等去重；未定义索引和未降低为连线的单项选择拒绝。未知或畸形操作不享受常量零成本豁免。

固定候选内按 `105/100*T0` 的约束减少真实共享寄存器位数，候选之间沿用冻结的字典序评分。两个候选在 PPA 之前按简单代价选出 `mul32_split16`；这不读取 TT 测量，也不表示在 1500 ps 下它是实测面积最优方案。

| L=2、II=1 | 原始 | 自动 split16 |
| --- | ---: | ---: |
| 最大级抽象代价 | 21 | 18 |
| 抽象组合成本 | 1024 | 1124 |
| 内部寄存器位数，含 valid | 65 | 129 |
| 内部寄存器信号数 | 2 | 6 |
| 区域内部寄存器数 | 0 | 5 |

实际切分是部分积后的一条边界：stage 0 产生四个部分积，stage 1 完成归约。p0 以 low/high 两个 16 位值跨级，p1/p2/p3 各 32 位跨级，共 128 位数据和 1 位 valid。表中不包含共同的外部输入/输出寄存器。RTL 外壳将输入事务在 tick t 采样，对应有效结果在 t+2 出现；这与 VUL 的 `N=L-1` 口径相同。

## 验证与物理结果

`regression/arithmetic_mul_split.py` 检查两个候选的真实 RTL，对照 Python 整数乘积，覆盖边界、所有单热位对、20,000 组随机输入、连续事务、气泡、六次复位和排空。另检查有收益的双出口整组移动、共享输入链只计一次、不完整/重叠组及被篡改调度被拒绝，并核对公开编译 API。

物理试跑由 `step5_pilot_v1.json` 在调用前冻结：每个候选一次 synth→grt，共 2 synth、2 grt、0 detailed，ABC=SDC=1500 ps，L=2、II=1、原生 RTL、TT/RVT/NLDM、固定种子/密度/利用率。无重试，无根据结果补点或重选。

| 同阶段 TT 指标 | 原始 | 自动 split16 |
| --- | ---: | ---: |
| synth 单元面积 / µm² | 562.29228 | 673.17318 |
| synth 最小时钟周期 / ps | 1076.43 | 863.97 |
| grt 单元面积 / µm² | 597.63420 | 707.08626 |
| grt 最小时钟周期 / ps | 1319.97 | 1082.01 |
| grt setup 最差 slack / ps | +180.028320 | +417.993195 |
| grt hold 最差 slack / ps | +1.329048 | +0.152725 |

面积包含物理单元/tap 并排除 filler；详细分项、关键路径、映射及物理网表、单元尺寸/缓冲清单、修复日志和 GNU time 记录随仓库归档。该单次探针的 grt 最小时钟周期减少约 18.03%，面积增加约 18.31%。两个点都有完整时序覆盖并满足本次 TT setup，hold 都处于 5 ps 复核带之下。没有重复性、详细布线、其他目标或多角签核结论；最小时钟周期不是纯组合数据段时延。
