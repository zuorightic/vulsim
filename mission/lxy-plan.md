# 复杂算术拆分与自动流水线化：实施规划

本规划依据 `mission/lxy.md` 和本地实际代码形成。用户已确认：使用 Yosys / OpenROAD，工艺使用 ASAP7 TT 角，按工作依赖和完成条件逐步推进。2026-10-23 修订时已核对新拉取的上游代码。本次仅更新规划及核验相关代码/工具行为，未修改编译器实现，未运行 ASAP7 面积或物理时序实验。实施步骤见 §10。

## 1. 目标和范围

在现有 VUL → RTLzz → RTL 流程中，增加可选择的算术展开、受给定端到端延迟和目标周期约束的流水线调度，以及基于 ASAP7 后端测量的方案选择。

第一版优化目标：给定端到端延迟 `L=L_fixed` 和目标时钟周期，在功能等价、启动间隔 `II=1` 的前提下，从规定预算内找到且通过验证的候选中，选择满足目标时钟、实测面积最小的方案。不承诺候选空间的全局最优；面积和时序均以指定后端阶段的实测结果为准。

首版将 L 作为输入约束，自动选择算术实现、拆分方式和内部寄存器位置；无需自动选择 L，也不以固定 L 实验宣称完成了跨延迟优化。固定 L 下的面积改善与时钟可行性由四组主实验评价。跨 `L <= Lmax` 的选择属于后续扩展，若执行，可进一步检验更低延迟与更小面积能否同时实现。

首版以整数乘法的内部自动拆分作为核心交付。整数除法和选定浮点操作必须完成接入、正确性验证及四组评估；其内部拆分模板数量和粒度由区域接入原型及三类算术接入步骤的验证结果决定。某类操作未开放内部拆分时，在清单和结果表中明确标注；该类的 C/D 可以退化为整算子调度，不能据此声称获得了该类内部拆分的收益。

| 必须交付 | 有余力再扩展 |
| --- | --- |
| 整数乘加、动态整数除法、选定浮点操作三类覆盖 | 更多位宽、有符号及混合符号语义 |
| 至少一种真正的内部自动拆分，优先保证无符号乘法 | 除法/浮点的多种切分粒度、更多乘法分块方式 |
| 候选生成、验证、ASAP7 评估、结果提取与选择闭环 | Wallace/CSA 等额外结构模板 |
| 六个正式案例、至少三个保留案例、四组主实验 | 大范围目标周期/延迟扫描及补充消融 |
| 明确语义、固定评估阶段、可复现结果 | 浮点加法、更多精度和舍入方式 |

建议的接入范围是无符号 16/32 位乘加与除法，以及固定舍入模式的 binary32 乘法。具体支持的位宽、输出截断和浮点语义须在主实验开始前冻结；首版不因减少扩展项而省略已有支持范围内的边界验证。

主实验先为每个案例固定一个目标周期，B/C/D 固定同一个端到端延迟 L。搜索主要覆盖已声明的模板和合法切分位置。多个周期及 `L <= Lmax` 的跨延迟搜索列为扩展实验。

先在显式声明的 `PIPELINE` 块及独立组合核上实现。既有 PIPELINE 的延迟是平台的周期行为契约：在固定声明下只能调整内部结构，不能由 RTL 后端擅自更改延迟。若后续执行跨 L 扩展，由实验驱动统一生成对应配置，同时供 simgen、rtlgen 和测试使用。

| `regression/mulu32/MulU32.vul` | 已有 32×32 乘法手工拆成四个 16×16 部分积的案例 | 作为自动拆分实现的功能参考及额外人工基线 |
| `rtlzz/scripts/differential_rtl.py` | C++ 与 RTL 差分验证、连续输入及流水线填充/排空 | 扩充新算术和周期对齐验证 |
| `regression/generator_pipeline*.py` | 平台级流水线、valid、实例化和仿真测试 | 验证接入后 VUL 平台行为 |

当前流水线代价主要是按操作类别给权重：Assign 为 0、Multiply 为 3、其余通常为 1；不区分位宽、实现和负载。它不是 ps，也不包含完整组合面积。

当前调度器固定 N 个内部寄存器边界，划分 N+1 个组合阶段。VUL `PIPELINE(latency=L)` 对应 `N=L-1`。RTLzz 命令行 `--latency N` 的数值却表示内部边界数，二者需要在新驱动中明确转换。

当前默认策略先得到估计时序基准 T0，再允许约 5% 的估计时序放宽以减少寄存器位数。它没有用户目标时钟的硬限制，单个 Mul/Div 也不会自动展开。仅调节现有权重不足以完成任务。

当前上游已支持原生与 CIRCT 两种流水线发射路径。RTLzz 的 CIRCT HW/Comb/Seq 桥接复用同一调度及寄存器表，支持 valid 使能和同步复位；VUL 的流水线分支已传递 `use_circt`。主实验首版固定使用原生发射器，CIRCT 可用于补充核对；若冻结前改选 CIRCT，四组须统一记录其版本与优化设置，不能按组切换发射器。

## 4. ASAP7 实验配置

后端固定使用用户指定的 ASAP7 TT 角。沿用以往实验脚本中的其他适用设置，并在项目实验配置中显式覆盖 ORFS 默认 corner。初始配置如下，其中 RVT、NLDM 沿用首版建议，TT 角已由用户确认：

```make
PLATFORM = asap7
ASAP7_USE_VT = RVT
LIB_MODEL = NLDM
CORNER = TC
```

本机 ORFS 使用 `TC` 表示 Typical case，该设置选择文件名含 `_TT_` 的 Liberty；因此使用 TT 角时配置写 `CORNER=TC`。代价微基准、物理误差审计、候选反馈、四组主实验及规定的物理复核统一使用这套 TT 配置。将实际库列表与哈希固化进实验清单；其他 corner 的数据不复用于本次模型、缓存或主结果。

PVT 记录以实际加载的 TT Liberty 为准。当前核对的 RVT TT 顺序库标称为 0.70 V、25°C，而平台 `TC_TEMPERATURE` 元数据写为 0°C；首次后端试跑前须核对并对齐实验元数据与实际库条件，报告记录实际采用值。

本地 ASAP7 Liberty 声明 `time_unit : "1ps"`。需要在读取库后核对 OpenSTA/OpenROAD 的 `report_units`，再生成 SDC、设置 ABC 目标和提取报告。驱动层统一使用带单位的 ps，保留原始值和原始单位，防止 ps/ns 换算出错。

每次运行固定并记录：

- ORFS、Yosys、ABC、OpenROAD 版本或提交号，实际加载的 Liberty/LEF 文件及哈希。
- VT、corner、Liberty 模型、时钟周期、不确定度、输入输出延迟、输入驱动及输出负载。
- 面积利用率、布局密度、RC 配置、线程数、可用的随机种子/确定性设置。
- 综合策略、加法器映射、层次展开、缓冲、时钟树、寄存器聚类等选项。
- 实际 `synth` 参数、算术映射相关选项和关键 pass 日志；必要时保留 coarse/fine 及算术映射前后的中间网表，使实际乘法映射路径可以追溯。最终时延与面积比例由固定后端流程测量确定。
- 同步复位、valid 写使能和边界寄存器策略。

初版保持单一 VT 和固定单比特触发器策略，避免混入多阈值及多比特触发器聚类的额外影响。直接复用平台的库列表和映射文件，不用通配符把不同 corner 或 `FAKE` 多比特触发器库全部读入。

评估分三层：

| 层次 | 用途 | 能说明什么 |
| --- | --- | --- |
| 综合映射 + STA | 建库、大量候选筛选 | 面积及单元时序估计 |
| CTS 后全局布线 + 寄生估计 | 搜索中的主要物理反馈 | 纳入布局、时钟树和互连影响的估计 |
| 详细布线后寄生提取及 STA | 根据后端试跑的资源测量确定最终评价或代表方案复核范围 | 仅覆盖实际完成详细布线的方案 |

在后端评估流程接通后，根据试跑的实际资源消耗，从以下两种评估口径中固定一种，并写入实验清单：

- 若预算允许全部主矩阵的最终入选方案完成详细布线，主表统一使用详细布线后结果。
- 若预算只允许代表方案详细布线，主表统一使用 CTS 后全局布线及寄生估计；另列详细布线复核表，结论只覆盖完成复核的方案。代表点按预先定义的覆盖/临界性规则选取，不只选择收益最大的点。

流程失败或未达到规定阶段的结果保留为空缺及失败记录，不借用更早阶段的指标补成同阶段结果。详细布线不能替换个别有利点的主表口径。

若 D 的最终阶段反馈显示候选未满足时钟，只能按预先规定的反馈/回退预算评估备选，或者明确报告失败。B/C 的最终测量不能触发按实测优劣重新选择；否则必须另行标记为不同选择方法。不能把全局布线结果写成详细布线结果，也不能用综合结果替代最终时序结论。

接通评估流程时完成真实后端试跑，记录综合、全局布线和详细布线的实测耗时、单作业峰值内存与线程数、允许并行的作业数，以及由此推算的总计算资源消耗。并行度在单作业资源需求测得后确定；超时、重试和失败保留规则见 §7.4。这些数据用于设置工具运行和搜索的资源上限，不用于规定实施阶段的日历进度。

## 5. 编译与搜索架构

```text
VUL PIPELINE / 独立组合核
          ↓
原有 S0–S11 + 组合 BEOPT
          ↓
建立或更新算术区域 / 候选展开
          ↓
受目标周期与延迟约束的调度
          ↓
既有寄存器物化、valid 对齐、复位求值、原生 RTL 发射
          ↓
正确性验证
          ↓
Yosys + ASAP7 + OpenROAD 评估
          ↓
结构化结果、缓存、可行性检查及方案选择
```

C++ 负责算术展开和流水线编译；Python 实验驱动负责候选枚举、缓存、工具调用、失败恢复、结果解析和选择。区域建立位置按 §5.1 的单一选定路线执行；图中的区域步骤表示候选生成前必须完成的区域检查，不限定身份一定在 BEOPT 后才建立。

候选展开放在 `PipelineV2.cpp` 的 `beir::opt::optimizeProgram(...)` 之后、`pipeline::build(...)` 之前。区域接入步骤通过原型选定“优化前建立并传播”或“优化后可靠识别”的一条最小可行路线，不要求同时完成两套实现。若使用模式匹配，必须检验误识别、漏识别及优化改变结构后的可靠性；两条路线各自的共享处理义务见 §5.1。

展开后只执行经过确认的清理，例如死代码删除和必要的常量处理，并同步更新区域元数据；寄存器物化后不再运行会跨级合并的组合优化。

保留“不展开”候选。拆分可能增加面积、布线和级间状态，并非所有案例都会获益。

### 5.1 算术区域与切分边界

算术区域是待实现、待验证的调度语义元数据，不以调试信息、源码行号或临时 NodeId 充当稳定身份。在区域最小原型验证完成前，不假设现有优化流程已能保留这些信息。区域描述至少包括稳定 region_id、原算子、语义配置、入口、出口、成员节点、模板版本和合法切分位置。它用于表达：

- A/B 中完整浮点操作等区域不可切分。
- C/D 中仅在已实现并声明的部分积归约层、除法迭代组或浮点结构边界切分；未开放的区域保持原子性。
- 不同模板和切分粒度对应相同原始功能。

按区域建立时机分别承担以下义务：

- **优化前建立并传播**：区域建立后，相关节点改写、别名替换、合并和重编号均须维护区域归属及端点映射，禁止不同区域内部运算节点跨区域合并。区域内部允许合并并同步更新映射。
- **优化后识别**：识别时必须检测前序优化已造成的内部节点共享。按冻结策略复制并重连以恢复唯一、非重叠归属，或拒绝该识别并回退到已验证的接入方式。仅在能证明完整操作原子性不变时，才可将共享节点归为明确输入边界；不能将任意内部共享重新命名为输入而绕过检查。

两条路线都在候选生成前检查成员唯一、区域非重叠、入口出口完整、依赖无环及完整操作原子性。原子性检查包含区域收缩后的依赖合法性，保证内部路径不会经外部共享节点绕过声明边界。区域内部子组和合法切分边界采用与选定路线一致的元数据承载/更新机制。若候选展开或后续清理改变区域，调度前再次执行这些检查。

区域建立后的元数据更新至少覆盖：

- 内联、克隆和模板展开：产生独立区域身份，记录新节点的归属、入口和出口。
- 节点替换、折叠和消除：同步更新成员及端点映射；语义出口被常量替代时仍保留出口映射，不留下悬空引用。
- 编号压缩和重排：使用显式旧→新映射更新节点引用，稳定 region_id 不随编号变化。
- 公共子表达式合并：按选定路线执行提前保护或既有共享处理，建立后的区域内部节点仍不得跨区域合并；明确输入边界和字面常量可共享。
- 区域校验：检查成员归属唯一、入口出口完整、依赖无环，以及合法切分点与当前节点图一致。上述原子区域首版不允许嵌套或重叠；浮点区域内的尾数乘法模板作为该区域内部的子图/调度组表达，不另建重叠的原子区域。

若采用复制重连，四组在共同预处理阶段使用同一策略，随后才按组决定是否展开及开放切分。记录保护/共享处理策略及版本、是否复制、复制节点数、拒绝原因和回退路线。编译图节点增量单列；复制不等同于最终面积增加，物理开销由后端统一测量。

区域在调度时可以收缩为原子节点，也可以展开为多个可调度组，在区域接入步骤选定具体方案。收缩必须保留到原节点的映射以及入口到各出口的组合路径信息，不能用成员时延简单相加替代区域关键路径。最终仍物化为标准 BEIR。选定路线的最小可用实现须在组约束首次端到端验收前完成；初始调度和后续优化遵守相同规则，具体工作和验收见 §7.2。

区域接入最小原型的验收项：

1. 单个选定浮点乘法能够生成 RTL，并用独立参考核对定向和有限随机向量；这不替代后续完整边界验证。
2. 两个浮点操作串联和并联时，区域身份及出口仍可区分，共享输入不会导致区域被合并。
3. 两个预期区域包含可被普通 CSE 合并的内部非边界节点：按选定路线验证提前保护能阻止合并，或优化后能检测既有共享并执行恢复、拒绝或有效回退；后续调度仍保持完整操作原子性。本项与共享输入用例分别验收。
4. A/B 中完整浮点区域不可内部切分；C/D 中只允许在原型声明的边界切分。若首版未开放浮点切分，C/D 也必须验证整个区域保持原子性。
5. 开启正常优化和区域校验后，上述性质仍成立，并覆盖节点替换、区域内 CSE、按路线处理跨区域共享及编号重排。任何恢复/回退后的图须重新通过功能及区域检查。

原型报告须给出路线选择、用例结果、必要改动清单、未通过项及剩余工作量。拒绝不可靠识别属于正确性保护，不代表相应案例已完成接入；没有可用的已验证回退而导致最低要求案例无法接入时，应明确标为未完成。

优先复用已有基础操作，避免首版新增大量发射器和复位求值都不认识的操作类型。尤其是现有 BEIR `Call` 在原生 RTL 发射和复位求值中不能作为外部算术 IP 黑盒使用。

## 6. 三类结构如何实现

### 6.1 整数乘法及乘加：第一个完整样例

第一种模板采用分块部分积。对于无符号 32×32 → 64 位乘法，以 16 位分块：

```text
a = a0 + (a1 << 16)
b = b0 + (b1 << 16)
p0 = a0*b0; p1 = a0*b1; p2 = a1*b0; p3 = a1*b1
a*b = p0 + ((p1+p2) << 16) + (p3 << 32)
```

实际 BEIR 必须为加法进位保留足够位宽，再按原输出语义截断，不能按上述数学式直接复用窄位宽相加。现有 mulu32 案例已演示中间 33/34 位进位与最终拼接，可作为实现参考。

最低交付保留原乘法，并实现一种分块模板，例如 32 位乘法的 16 位分块；切分点位于部分积产生、部分积归约及最终进位加法之间。8 位分块及更多位宽列为扩展，carry-save/Wallace 等结构模板也在主实验完成后再考虑。

乘加保留 `a*b+c` 的原位宽和截断位置。整数的重组必须在模运算语义上证明等价。若扩展有符号和混合符号操作，要逐个保留操作数的 `signed_view`，明确扩展和截断规则；不能把无符号公式直接套到原始位模式。

验收除了结果正确，还要查看生成 RTL 或调度报告：原本单个 Mul 对应的内部结构确实跨越了寄存器边界。

### 6.2 整数除法：先接入与定义语义，再开放内部切分

最低交付首先接入动态无符号商余核、统一除零包装及复位规则，完成四组流程。内部切分可采用无符号 radix-2 恢复余数式除法：W 位操作展开成 W 个空间迭代步骤，各步包含移位、比较/减法、商位选择和余数更新。

根据除法接入验证结果决定是否纳入内部切分，以及采用的一种基础分组粒度；每 1/2/4 步的完整粒度集合列为扩展。启用时，由调度器在组之间插寄存器，同步传递部分余数、商、除数及剩余被除数状态。未启用时，C/D 在除法区域保持原子调度，并在结果中标注 `internal_split_enabled=false`。

这是空间展开后的流水线，目标仍为 II=1。使用一个减法器循环 W 次的实现具有不同的吞吐行为，不计入这组固定 II 对照。

除数必须是动态输入；仅测试除以 2 的幂会被现有优化化成移位或切片，无法证明复杂除法拆分能力。

语义先在统一测试包装中定义：

- 主范围先覆盖无符号 16/32 位。
- 建议对除零显式约定 `q=全1，r=被除数`，并让所有实验组使用同一带保护的包装；不改变平台原有 `/` 的未定义或工具相关行为。
- 包装同时保证所有内部寄存器的复位表达式有定义，不能只在最终结果上选择除零输出。例如先生成 `safe_d = (d == 0) ? 1 : d`，商余核只使用 safe_d；最后按对齐的 `d == 0` 标志选择约定结果。被除数、除零标志和正常商余路径必须按事务对齐。
- 检查优化后实际除法/取模节点及展开结构仍只消费安全除数；若编译器重写导致内部复位求值出现未定义表达式，候选验证失败。该性质须覆盖不同调度结果，不能假设复位求值只访问最终被选择的分支。
- 如果增加有符号除法，额外定义向零截断、余数符号和最小负数除以 -1 的行为。

必测除数复位值为零、连续正常输入中穿插除零事务、不同已支持的内部切分位置，以及有在途事务时复位。若除法切分未开放，覆盖不同算子间调度与延迟，并在测试报告中将内部切分项标为未支持。

A/B 在紧时钟下不可行是正式实验结果，保留其面积、时序和失败原因。不为通过目标而改成 II≠1 的迭代实现；不同 II 的实现只能作为额外参考。

除法案例中，B 表示现有算子间调度与固定综合流程对未显式展开的 `/`、`%` 实现共同产生的结果。它是未展开实现的实测参照，不代表其他除法结构或调度方法的性能上限。

### 6.3 浮点：限制范围，尽早验证接入路径

现有 Clang 类型降低仅覆盖 bool、整数、Int、数组和结构体等，不能直接把 `float/double` 放进源程序就得到浮点 RTL。

建议首版使用 binary32 乘法，输入输出采用 `Int<32>` 位模式，并携带异常标志。理由是可以复用整数乘法拆分，且只涉及一个最终舍入点，不引入 FMA 与分离乘加的语义差别。

采用已有算术实现的结构和算法，候选来源可评估 Berkeley HardFloat 等；用 Berkeley SoftFloat 的 `f32_mul` 等独立模型作参考。当前尚未完成所用实现的选型、下载、适配和测试，不能把它当成已经接通的能力。

浮点接入优先验证位向量结构适配路径：将所选 binary32 乘法实现适配为现有 Int/BEIR 能表达的组合算术区域。最低交付保证整区域接入、参考核对及四组评估；是否开放及开放多少内部切分边界，由区域原型与浮点接入验证结果确定。候选边界如下：

```text
解包、分类、非规格化输入处理
          ↓
符号/指数计算 + 24×24 尾数乘法
          ↓
规格化、移位、guard/round/sticky 信息
          ↓
一次最终舍入、打包、异常标志
```

位向量 helper 经前端内联后，按 §5.1 选定路线及其条件建立完整浮点操作区域；不默认身份必定在 BEOPT 前建立。该机制目前待验证，只实现一条最小可行路线。A/B 将完整区域作为原子操作，C/D 仅开放已声明并通过验证的内部边界；若未开放浮点内部切分，则四组都保持完整浮点操作的原子性。不能因 helper 展开成整数节点而让 B 意外进入浮点内部切分。

区域接入步骤需给出单操作 RTL/独立参考核对、双操作身份与出口区分、内部非边界共享处理、切分限制及正常优化下区域有效性的最小原型证据，具体完成条件见 §5.1。共享输入与内部 CSE 两类用例分别验证；路线拒绝/回退状态计入接入完成情况。

如果现有实现只有 Verilog，必须显式完成结构适配或引入受约束的阶段模块适配器；仅在生成目录复制 `.v` 文件不能让当前调度器切入 IP 内部。库格式和语义兼容性须在区域接入原型中验证，再依此推进正式集成。

浮点语义建议固定：round-to-nearest ties-to-even、支持零/负零/Inf/NaN/非规格化数，不采用 FTZ/DAZ；NaN 规范化方式和 signaling NaN 的 invalid 标志、下溢检测时机及其他异常标志在实验清单中明确。所有组使用同一约定，数据和标志一同延迟对齐。保持每个浮点操作的舍入位置和顺序。

## 7. 代价规则、调度与搜索

### 7.1 先建立小数据库

使用结构化查询特征：操作类别、各输入/输出位宽、符号解释、常数特征、模板、拆分粒度、估计扇出及库/流程指纹。后端测量统一来自 §4 冻结的 ASAP7 TT 配置，corner 和库内容哈希参与模型身份及缓存指纹。

微基准优先覆盖主实验实际使用的位宽、模板和合法切分单元：

- 主案例及中间进位所需位宽的加法与比较；更广的 8/16/24/32/64 位网格属于扩展。
- 主案例使用的乘法及已实现的部分积模板。
- 完整除法核；已开放内部切分时再采集对应迭代组。
- 完整浮点区域；已开放内部切分时再采集对应关键段。
- 带 valid 使能和同步复位的寄存器及其控制开销。

优先使用查表和分段插值，缺项时用保守估计并标注来源。初版无需复杂机器学习。单元时延与互连时延分别保留，避免在路径上重复计入整条边界开销。

组合面积按互不重复的原子/区域实现计数；寄存器使用现有跨级活跃值和共享延迟链算法。不能把整块模板面积与其所有内部节点面积再次相加。

B/C 解析规则的物理误差审计按“先冻结，再查看和报告”执行：在查看用于审计的 ASAP7 微基准测量结果前，冻结 §7.5 的解析公式、参数、规范化/位宽规则和选择策略，并记录版本、内容哈希及冻结时间。随后将 16×16→32 与 32×32→64 无符号乘法的实测时延比，与解析规则隐含的抽象时延比并列报告；不据此调整 B/C 的规则。

这两项测量使用一致的评估阶段、ASAP7 TT corner、时钟/负载约束、输入驱动和输出负载，并给出路径时延定义，例如统一边界壳内算术数据路径的最大组合单元及互连时延，寄存器/时钟开销单列。报告使用“实测时延比”，不将其称为逻辑深度比。D 可以使用按其建库规则采集的数据建立物理模型；B/C 的冻结规则不吸收该标定信息。

时延比只用于解释简单模型的局限，不证明模型误差的固定方向、某个候选必然被选中或 C→D 收益的上界。后续若研究后端标定的简单模型，可另列选做的 `C_calibrated`，不改变四组主实验，也不占用主矩阵预算。

### 7.2 工作项一：组约束贯穿调度全过程

该项独立于物理时间建模，先在简单代价下验证。初始可行性调度、阶段代价计算、寄存器成本计算、局部优化及最终合法性验证使用同一份区域/切分规则。

在实现组约束调度前选定实现方式：若采用区域收缩，保留组到原节点的完整映射、入口到出口的路径代价，以及组外真实活跃值和共享延迟链，不能把组的全部成员输出都视作需要跨级保存。若直接调度节点图，则必须有合法的整组放置/移动操作，不能仅依靠单节点移动后再检查。

验收必须包括：

1. 初始调度不会拆开不可切分组，已声明边界之外没有寄存器。
2. 减少寄存器的局部优化不会破坏分组，最终合法性检查能拒绝故意构造的违规结果。
3. 存在收益的合法整组移动能被尝试和接受，不被单节点机制意外阻止。
4. 组内关键路径、组外寄存器位数与展开后图一致，包含多出口和共享跨级值。
5. 无法放置的组返回具体组号、边界/级数约束及代价原因。

### 7.3 工作项二：目标周期转成一致的数据路径预算

保留现有旧权重模式用于兼容检查；D 引入按节点/区域特征查询的 CostProvider，使用明确的 ps 单位。B/C 的简单规则单独定义于 §7.5，不能将其抽象数值直接当作物理时间。

用户目标周期先转换为数据路径预算。对于寄存器到寄存器路径，按约定扣除 clk-to-Q、setup、不确定度以及保守的时钟/互连预留；外部输入输出路径按相同 SDC 的 I/O 延迟单独处理。对于实际为组合 wiring 的路径也按对应约束处理。预算分量和来源写入报告，避免和单元/互连模型重复扣除。

固定 L 后，D 的初始可行性调度、局部面积/寄存器优化和最终估计检查统一使用该预算。若保留相对基准的 5% 放宽，T0 必须是该候选固定 L、同一物理模型下建立的基准，单位为 ps，并记录基准调度对各路径类型的最大估计延迟 `T0[p]`。同一路径类型 p 的局部优化允许上限同时受 `1.05×T0[p]` 和绝对数据路径预算 `B[p]` 约束，即 `Tmax[p] <= min(1.05×T0[p], B[p])`。统一预算特例可使用一个 T0 和 B；不同路径类型分别检查，不能解释为允许超过用户预算 5%。若任一路径类型无法满足预算，则候选估计不可行。

单个不可切分组超过预算时，返回该组及违约原因，由驱动尝试已支持的更细模板；不能用完整算子前后的寄存器宣称解决内部关键路径。寄存器物化和 valid/reset 仍复用现有逻辑。

分别记录 `estimated_feasibility` 和 `measured_feasibility`：前者来自指定模型和预算，后者来自统一评估阶段的 STA。B/C 没有物理预算预测时，前者填“不适用”，不能把抽象代价较低等同于估计时钟可行。代价模型用于筛选；最终是否满足时钟由 ASAP7 流程判定。验收覆盖预算换算、非正预算拒绝、5% 放宽越界阻止，以及估计可行但实测失败的状态区分。

### 7.4 有限预算搜索、资源与失败处理

首版在输入的固定 L 下采用确定性的有限候选枚举，不枚举或自动改变 L；小规模束搜索为候选数量确有需要时的扩展。保留原实现，优先对关键路径上的重算术节点尝试已支持的模板。C/D 使用同一候选生成器和相同允许范围，不将 D 额外发明的模板混入对照。

完成后端资源试跑后，为每案例/组固定以下独立上限：

| 预算项 | 规则 |
| --- | --- |
| 候选数量 K | 按固定顺序最多生成 K 个不同配置，C/D 使用同一上限；记录合法、非法和实际编译数量 |
| 综合次数 S | 区分候选搜索、最终测量和建库调用；B/C 不用搜索测量选优，D 可在上限内使用 |
| 全局布线次数 G | 固定 D 反馈上限以及各组最终评价所需次数；分开记账 |
| 详细布线次数 R | 与 §4 冻结的评价口径一致，另列最终评价/代表复核及 D 允许的回退次数 |

这些预算不要求两组消耗同样数量的后端调用。需分别报告实际使用量、缓存命中、重试次数和超时；共同的最终评价不能伪装成选择器可见的免费反馈。预算数值在试跑后填写并冻结，未填写前不启动主矩阵。总预算同时覆盖微基准建库、原型验证、首版 36 条案例/组记录所需的评价、搜索及规定的物理复核。

缓存键覆盖源码/BEIR、优化配置、简单代价规则及成本评估阶段/规范化/位宽提取版本、模型版本/内容哈希、语义配置、区域模板/边界版本、区域接入路线、保护/复制/拒绝/回退策略及版本、L、约束、库指纹、发射器、工具及流程设置。运行结果记录实际复制/回退状态和规范化后图哈希；改变任何影响行为或选择的配置均使相应缓存失效。候选失败记录阶段和原因，不能把超时、未约束路径或解析失败当作优秀结果。

只有通过功能、组约束和 L/II 检查的候选才参与性能选择。D 在同一反馈阶段的完整已测候选中，以时钟可行为前提，按 `(实测面积, -setup_wns, -hold_wns, 寄存器位数, candidate_id)` 字典序选优。不得将综合与布线结果混在同一排名中。若无已测可行候选，以 `max(0,-setup_wns,-hold_wns)` 最小、再按面积和 candidate_id 的顺序保留功能正确的诊断候选，并明确失败；未约束路径或不完整 STA 不进入此排名。若没有有效实测，只能输出带状态的估计候选或失败记录，不能宣称可行。最终阶段回退也受相同规则及预算约束。

### 7.5 B/C 简单代价与 C 组选择规则

主实验 B/C 采用同一份、完全不读取 ASAP7 测量的简单解析规则；旧权重运行模式保留为兼容检查或补充 `B_legacy`，不额外占用四组主实验的位置。统一简单规则可减少完整算子与展开图的计量粒度差异。以下保留 v1 的主要公式和系数；先做结构检查和功能原型，在查看 §7.1 物理误差审计数据前冻结公式、参数及选择规则，不根据微基准审计或正式/保留案例的 PPA 调整。

令 `w` 为当前操作有效输入/输出的最大数据位宽，`h(w)=max(1,ceil(log2(w+1)))`。`d` 为抽象时延，`a` 为抽象组合成本，二者没有 ps 或 μm² 含义。

成本评估阶段统一规定为：组合 BEOPT、选定路线的区域检查/必要恢复、该候选的展开，以及冻结的清理/宽度规范化完成后，流水线调度和寄存器物化之前的 BEIR。原实现和展开候选使用同一套规范化、位宽提取及选择节点分派规则；清理不得消除候选声明的合法边界或破坏区域原子性。调度读取该规范化图的代价，报告保存此阶段的图/哈希和规则版本。

本版按以下规则确定有效位宽：

- 无符号输入根据可证明的高位零信息确定有效位宽，零扩展新增的高零位不增加有效乘数位宽；无法证明可缩减时使用输入类型位宽，最小按 1 位。只使用此阶段的静态事实，例如已验证且有效的 `known_zero`，不依赖测试向量的偶然数值；输入数据位与索引/条件/进位等控制位按冻结的算子角色区分。
- 对乘法，`w=max(有效乘数位宽 m, 有效乘数位宽 n, Mul 输出类型位宽 r)`。抽象时延使用这个 w，抽象组合成本使用 `m×n`；两种启发式特征不同，不要求同用一组位宽特征，也未作物理标定。
- Mul 输出计费位宽取该阶段节点的输出类型位宽。后继截断不会自动更改它；合法优化已经将 Mul 窄化时，按窄化后类型计费。允许功能等价的提前窄化，不为保持模型数值禁止合法优化。
- 选择/查表节点的 w 为数据备选的有效位宽与输出类型位宽的最大值，不将条件/索引位宽当作数据位宽。其余节点沿用有效数据输入/输出的最大位宽定义；数组先按冻结规则映射到实际标量选择。

| 节点类别 | d | a |
| --- | --- | --- |
| 赋值、静态切片/拼接、常量移位、扩展/截断等布线 | 0 | 0 |
| 位运算、取反、逐位逻辑、二选一 mux | 1 | w |
| 加/减/进位加法、整数比较 | h(w) | w |
| 乘法 | 3×h(w) | 两个有效乘数位宽的乘积 |
| 完整无符号除法/取模 | w×h(w) | w²；只有显式共享的商余实现才计一次 |
| 动态移位/位选/切片/写入和归约 | h(w) | w×h(w) |
| 含 k 路的选择/查表 | max(1,ceil(log2(k))) | k×w |

乘法示例假设输入均具有完整有效位宽：

| 成本评估时的 BEIR 形态 | Mul 输出位宽 | 节点抽象时延 d | 节点抽象组合成本 a |
| --- | --- | --- | --- |
| 32×32→64，保留完整乘积 | 64 | 3×h(64)=21 | 1024 |
| 32×32→64，后接截断到 32，Mul 尚未窄化 | 64 | 21 | 1024 |
| 32×32→32，Mul 已窄化为仅产生低 32 位 | 32 | 3×h(32)=18 | 1024 |
| 16×16→32，保留完整乘积 | 32 | 18 | 256 |

“保留完整乘积”表示保留完整乘积位数；只保留低 k 位表示模 `2^k` 的结果语义。后继截断按上述布线规则计零成本。表中相同的抽象组合成本不代表完整与截断乘法具有相同物理面积。上述数值是节点代价；拆分候选的最大级代价还需在固定 L、归约结构和合法切分边界约束下通过调度计算。

选择节点按以下顺序唯一分派，避免同时套用二选一与 k 路规则：

1. 先按冻结规范化做安全常量/可达性简化。只有一个备选且能证明可化为连线时，先化为连线，再按零成本布线计费。
2. `Ite` 的两个数据备选使用二选一规则：`d=1，a=w`。
3. `Case` 保留第一个成立条件优先的语义。k 是规范化后剩余的数据备选数量，包含保留的默认分支，即剩余条件—数据对数加一；不将条件操作数计入 k。两个数据备选使用二选一规则，超过两个使用表中 k 路公式，不将优先语义假设为平衡树实现。
4. `Lookup` 的 k 是规范化后按静态索引事实可达的表项数量。首版按该节点规范化后的索引语义、索引类型、已证明的高位零/常量信息和合法表项范围确定一个保守可达集合；包括已有合法索引截断/掩码等规则，未知关系保留所有可能表项，不按样本输入缩减。不因备选数值恰好相等而额外去重，除非规范化已完成对应功能等价重写。两项使用二选一规则，超过两项使用 k 路公式；单一备选不能安全化为连线或存在未定义索引时，先显式降低并确定语义，无法完成则拒绝候选，不临时选取某个公式。

多路选择公式是抽象近似，不意味着实际硬件必然采用平衡选择树。规范化/可达集合和分派规则固定版本；遍历顺序不得改变 k 或计费类别。

复合操作按已验证的结构降低为以上节点；所有可达算子必须有明确规则，未知操作不能静默使用零成本。纯常量子图不计事务路径时延和寄存器成本。

| 项目 | 冻结的规则 |
| --- | --- |
| 区域代价 | 对浮点等多节点区域，在完整组合 DAG 上按关键路径计算 d、对实际共享节点各计一次 a；不可切分只限制放置，不把区域时延改成成员之和。完整整数 Mul/Div 使用上表公式 |
| 寄存器/控制成本 | 使用物化后的共享跨级寄存器位数，包括 valid 链；每保存 1 位增加 1 单位抽象成本。模板显式引入的 mux/控制逻辑按同一节点表计费 |
| 单候选调度 | 固定 L，通过可行性搜索建立该候选最大流水级抽象代价的基准 T0，再在 `Tmax <= 1.05×T0` 内减少抽象组合成本加寄存器成本；按 §7.2 做合法整组移动，不宣称得到全局最优。此 T0 为抽象量，与 D 的 ps 基准分别记录 |
| 跨候选评分 | 对最终合法调度按 `(最大级抽象代价, 抽象组合成本+寄存器位数, 寄存器位数, 寄存器数, candidate_id)` 字典序选择 |
| 并列处理 | candidate_id 来自规范化配置及固定枚举顺序；遍历次序、数值比较精度和局部移动并列规则一并冻结，不使用运行完成先后次序 |
| 目标周期 | 主矩阵固定同一 L；B/C 不使用用户的物理目标周期，不将抽象代价换算成 ps，但保留单候选的抽象 T0 搜索及其 5% 上限。选定后由共同后端流程判定真实时钟可行性 |
| 跨延迟扩展 | 主实验不搜索 L；扩展扫描在预先固定的每个 L 独立选择并报告。用最终实测跨 L 选优属于额外方法，不混入 C 主结果 |
| 失败处理 | 无合法候选返回明确失败；已选候选实测未达时钟则保留该失败，不按测量反馈重选。编译/功能验证失败可以按固定排序取下一合法候选，受同一预算限制 |

冻结前进行结构检查：相同功能不同表示下的零成本布线、有效乘数位宽、进位加法、截断表示、选择分派及商余共享是否按同一规则计费；用最小原型核对两类候选的合法比较。规则冻结后才进行 §7.1 的物理误差审计，并报告上述全位宽乘法的抽象时延比 `18/21=6/7` 及同方向的实测时延比，不能据此重调 B/C。比例不构成选择结果或方法收益的证明；若简单规则表现出系统性偏好，应解释局限而非回写标定信息。

## 8. 四组实验如何保证有效

| 组别 | 算子内部切分 | 选择时使用 ASAP7 代价 | 含义 |
| --- | --- | --- | --- |
| A 原始组合 | 关闭 | 不使用 | 原始未流水化数据路径，保留统一边界寄存器 |
| B 算子间流水化 | 关闭 | §7.5 简单解析规则，不读取实测反馈 | 相同简单规则下的整算子调度 |
| C 拆分 + 简单代价 | 在已支持区域开启 | 与 B 相同的简单规则，不读取实测反馈 | 目标无感的简单代价基线；固定 L，优先比较最大级抽象代价，再比较组合与寄存器成本，真实时钟可行性由共同后端判定 |
| D 拆分 + 后端感知 | 与 C 相同 | 后端代价模型及规定预算内的实测反馈 | 模型与反馈策略组成的整体选择方法 |

所有组最终都通过相同 ASAP7 流程测量，C 也需要后端报告；但 C 的选择器不能利用该报告重新选优。C/D 使用同一模板集合、区域切分支持范围、固定 L、语义和候选数量上限。候选、综合、全局布线、详细布线及总时间分别按 §7.4 设上限并报告实际用量，不要求两组耗尽相同数量的后端调用。

B→C 用于评估相同简单规则和固定 L 下开放内部拆分的效果；C→D 用于评估后端模型和规定反馈策略组成的整体选择方法。C 的目标无感指不读取物理目标周期，不删除其单候选 T0 搜索及 5% 局部放宽。主实验不单独归因于“模型”或“在线反馈”。若需要区分，额外增加 `D_no_feedback`：使用相同模型和候选集，但选择前关闭在线测量，只保留共同最终评价；该项与 §7.1 的 `C_calibrated` 均为选做，不增加主实验组或挤占主矩阵。

未支持除法或浮点内部切分时，相关区域在 C/D 仍保持原子性；其结果只说明整操作调度/选择，不计为该类内部拆分证据。所有结果记录每类操作实际支持的边界。

主实验中，B/C/D 对同一案例使用相同的一个 L，直接评价 §1 的固定延迟目标，不以跨 L 最优替代固定 L 对照。A 原始版本的 L 通常为 1，应单独展示其延迟；若另做输出延迟补齐版本，要标明补齐寄存器及面积。多个周期、多个 L 及 `L <= Lmax` 的各自最优比较均为扩展实验，不增加为首版验收必做项。

主矩阵的结论限定于固定 L、目标时钟及规定搜索预算。只有实际执行跨 L 扩展并验证对应方案时，才报告更低 L 下的面积改善或跨 L 的候选选择；“同时降低 L 和面积”属于可报告的额外收益，不是首版完成门槛。

## 9. 正确性和结果验收

验证分为两个层面：

1. 展开前后组合函数等价。小位宽整数可穷举，较大位宽使用定向/随机及可行的形式验证。整数参考使用明确位宽的位向量运算，避免 C++ 有符号溢出等未定义行为。
2. 插入寄存器后输出事务序列等价。使用队列 scoreboard 按 L 对齐，覆盖连续输入、valid 气泡、填充、排空、长短路径合流和运行中复位。

整数边界包括已支持范围内的零、全 1、最高位、进位传播、截断及定义好的除零情况；扩展有符号/混合符号时再增加相应边界。除法专项覆盖：除数复位为零、连续输入穿插除零、不同已支持的内部切分位置/调度结果，以及在途事务复位，检查内部复位表达式和最终输出都有定义。浮点使用独立参考，覆盖正负零、Inf、quiet/signaling NaN、非规格化数、舍入临界、溢出和下溢，比较位模式及约定的异常标志。

不要在每个输入之间清空流水线，否则无法检出跨事务混线问题。现有 simgen valid 测试及平台流水线测试需继续通过。

正式面积使用后端同口径的标准单元面积，内部寄存器位数用于解释原因，二者不可互相替代。时序同时记录约束、WNS/TNS、关键路径和是否存在未约束端点。不能仅由含时钟树/外部延迟的 slack 随意反推出一个“组合时延”。

区域保护/共享恢复发生在共同预处理阶段，其策略、实际复制及回退状态和图节点增量可追溯到 manifest。图节点增加与最终物理开销分别报告；未可靠识别且无已验证回退的案例计为未完成接入。成本抽取还需核对所保存评估图上的乘法位宽与四种截断示例、Ite/Case/Lookup 唯一分派及确定的 k；B/C 的冻结记录须早于物理误差审计，不能从审计结果回写解析规则。

在查看主实验结果前冻结评价方法：

1. 入选方案必须通过正确性、L 和 II 检查；未通过的候选不计为性能改善。某组没有有效候选时保留失败记录，不能删除案例。
2. 真实时钟可行性按统一阶段和 SDC 判定，检查 setup、hold 及未约束路径。估计可行不代替实测可行。A/B 在紧时钟下的不可行结果保留其已测面积、时序和原因；流程未完成时只报告已获得的阶段数据及缺失状态。
3. C/D 都可行时比较面积，报告绝对差和相对差；只有一组可行时报告可行性差异，不把不可行方案的面积优势算作优化成功。两组都不可行时报告违约程度，不能计作满足目标的收益。
4. 同时报告搜索墙钟时间、正确性验证和最终评价耗时，以及各类后端调用数。将建库的一次性成本单列，说明是否摊销及其方式。
5. 全部预定案例逐例报告，包括退化、无收益和失败。汇总可行率时说明分母；跨案例面积汇总只在双方均可行的集合上进行，并明确集合与统计方法。

不设置“D 至少在若干案例不劣于 C”或预期提升百分比等完成门槛。根据实际结果解释拆分收益、寄存器/控制开销、互连或模型误差；不存在负例时不人为制造负例。未执行模型/反馈分离消融时，只报告 C→D 整体选择方法的差异。

重复测量采用条件触发：先在固定设置下确认流程确定性；对接近时钟边界、收益很小或对线程/种子等设置敏感的代表点追加重复运行，并将实际设置、运行次数和指标变化范围一起报告。若变化范围影响胜负或可行性判断，应标为不稳定结论。没有实测证据前不设所谓固定的 ps 噪声底；重复运行也计入冻结的资源预算。

## 10. 按依赖推进的实施步骤

以下九步按技术依赖逐步完成，每一步都给出工作内容、产出和完成条件。已有证据可以复用，仍被阻断的项目继续处理。步骤完成后再进入依赖它的下一步；过程中发现影响前置条件的问题，返回对应步骤修正并更新记录。

§3 保存当前已执行的环境和功能检查，§4–§9 提供技术细则，本节作为实施时的执行顺序。工具超时、搜索耗时和计算资源预算仍按 §7.4 管理，它们用于保证实验可运行、可复现。

### 10.1 步骤一：修复并确认现有功能基线

工作：复用 §3 的构建、安装和测试记录，处理原生 AddCarry 位宽问题以及 Verilator 宽端口驱动兼容问题。重跑此前被阻断的 pipeline 多延迟、结构体打包、valid、复位及 mulu32 回归，固定主实验使用的发射器和工具版本。

产出：最小修复及相关回归结果、当前工具/源码版本清单、可重复运行的原始案例及日志。

完成条件：主实验需要的原生 RTL 生成与仿真路径通过相关基线；兼容性处理方式有记录，未通过或未运行的其他路径明确标注。当前已确认构建和 CIRCT 安装有效，但本步的两处基线故障仍待处理。

### 10.2 步骤二：定义算术语义、对照规则和案例划分

工作：按 §1、§6、§8 明确整数位宽/截断/除零和浮点操作/舍入/特殊值语义，落实独立参考模型与除法安全包装设计。确定六个正式案例、三个保留案例及其与建库微基准的划分；定义目标周期和固定 L 的制定规则。按 §7.5 做 B/C 解析规则结构检查，并在查看物理误差审计数据前冻结公式、参数和选择策略。

产出：版本化语义配置、参考模型接口、案例清单、B/C 简单代价及选择规则、目标制定规则和对应测试要求。

完成条件：三类结构的功能含义和四组差异明确；B/C 的规则及冻结记录可追溯，保留案例不参与调参。实际目标数值可在后端试跑和微基准完成后按规则填写，但不能依据主结果反复选取。

### 10.3 步骤三：接通 ASAP7 TT 后端评估与结果提取

工作：把现有 RTL 接到 Yosys、OpenROAD 和 ASAP7 TT（`CORNER=TC`），核对真实库列表、单位及 PVT 元数据。完成单核综合、全局布线和详细布线试跑，自动提取面积、时序和失败状态，记录耗时、内存及并发资源需求。根据实测确定统一主表阶段、详细布线复核范围和初始搜索资源上限。

产出：可重复的评估脚本、TT 配置/库指纹、原始后端报告、结构化指标，以及工具调用、超时、重试和资源约束。

完成条件：至少一个原始算术核能够从生成 RTL 走到选定评估阶段并输出可核对的指标；失败能定位到具体步骤。评估阶段和物理复核范围有明确决定，后续候选可直接复用该流程。

### 10.4 步骤四：验证并实现最小算术区域接入

工作：按 §5.1、§6.3 验证浮点实现与参考模型的最小接入，通过原型选定优化前传播或优化后识别的一条路线。实现必要的元数据承载、节点/端点映射、共享处理及原子性检查，覆盖共享输入和可被普通 CSE 合并的内部节点两类用例。

产出：区域原型及选定路线的最小可用实现、用例结果、必要改动清单、恢复/拒绝/回退记录和剩余工作清单。

完成条件：§5.1 的区域检查成立；单操作与双操作的身份、入口和出口可追溯；A/B 不进入完整操作内部切分，C/D 只使用已声明边界。该实现必须先于组约束的首次端到端验收；没有已验证回退的识别失败不算接入完成。

### 10.5 步骤五：完成组约束调度与乘法内部自动拆分

工作：实现 §7.2 的初始组调度、阶段/寄存器成本计算、整组局部移动和最终合法性检查。在其上实现一种乘法分块模板，复用 valid 对齐、复位求值和 RTL 发射。先在固定 L、简单代价下，打通自动展开、验证、调度、RTL 生成和 TT 测量。

产出：原始 Mul 与自动分块候选的 RTL、功能/周期验证结果、区域/流水级报告及同阶段 TT 指标。

完成条件：§7.2 的组约束验收通过；至少一个原始单 Mul 自动展开后，内部确有寄存器跨过其算术结构，并在连续输入、气泡及复位下结果正确。这一步形成首个完整优化闭环，不要求此时已经建立物理代价模型。

### 10.6 步骤六：完成整数除法和选定浮点操作的正式接入

工作：在既有区域与流水线流程上完成动态商余和 binary32 乘法接入，落实步骤二的语义及独立参考核对。验证除数复位为零、穿插除零和在途复位，以及浮点特殊值和舍入边界。依据接入结果确定是否开放及开放哪些除法/浮点内部切分边界。

产出：三类结构都可编译、验证和后端评估的案例；支持范围/边界清单、参考核对结果及未支持项说明。

完成条件：三类代表结构均完成接入并可进入四组流程，已支持语义的边界验证通过。乘法内部拆分保持可用；其他操作未开放内部切分时，C/D 保持原子调度并明确标注，不能宣称该类内部拆分收益。

### 10.7 步骤七：建立 TT 代价模型并实现 D 组自动选择

工作：采集实际模板和位宽所需微基准，按 §7.1 建立带来源的代价库；冻结后审计 B/C 的物理误差。实现 §7.3 的路径预算及目标周期约束，再按 §7.4 接通固定 L 下的候选生成、模型筛选、规定反馈、缓存和确定性选择。分别验收组约束与物理预算，区分估计可行和实测可行。

产出：版本化 TT 代价库、成本查询接口、目标周期调度器、可重复的 C/D 选择器及 manifest/缓存记录。

完成条件：对代表案例可自动完成候选生成、正确性检查、TT 评估和方案选择；无可行方案时返回明确原因。C 不读取实测反馈选优，D 仅在规定预算内使用反馈；目标周期、L 和 II 不被静默放宽。

### 10.8 步骤八：冻结并执行四组主实验

工作：补齐并冻结主矩阵的实际目标周期、固定 L、C/D 规则、D 模型、候选/后端调用/资源上限和统一评价阶段。对六个正式案例、三个保留案例运行 A/B/C/D，执行规定的物理复核与条件触发的重复测量，按 §9 汇总全部可行、退化和失败结果。

产出：36 条案例/组记录、入选 RTL、正确性结果、原始与结构化后端报告、搜索日志、资源统计和固定 L 下的对照分析。

完成条件：36 条记录均有结果或明确失败状态；支持结论能追溯到对应 RTL、配置和报告。B→C 和 C→D 的贡献按 §8 限定，保留案例不回填全局模型。不预设 D 的胜率或面积收益幅度。

### 10.9 步骤九：复核结果并整理交付

工作：检查结论、语义、工具/库版本、缓存指纹和后端阶段是否一致，从冻结配置复现代表结果。整理拆分/调度/选择程序、代价库、生成 RTL、验证脚本、报告和使用说明，完成 §12 的交付项。

产出：可构建代码、单命令复现入口、完整交付清单及方法局限说明。

完成条件：交付物和结果相互对应，复现过程可执行，最低要求逐项有证据。完成后再根据需要开展额外模板、跨 L 搜索或补充消融；这些扩展单独配置和报告。

执行过程中若资源开销过大，依次缩减额外模板、除法/浮点内部切分粒度、周期/延迟扫描和补充消融；三类覆盖、至少一种真正内部拆分、四组主对照、保留案例、正确性及统一评估口径仍须保留。

主矩阵冻结后，如发现影响正确性或比较有效性的缺陷，记录原因、更新版本并重跑受影响结果。未完成项如实报告；不能通过事后修改评价规则或最低要求来消除失败。
